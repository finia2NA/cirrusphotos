# Architecture

This document is the source of truth for current technical structure, subsystem boundaries, data flow, and invariants. See [PROJECT.md](PROJECT.md) for user-visible behavior and product scope.

## System and browser

`TimelineCore` contains the platform-independent navigator model. `SynologyAPI` separates wire/domain models and the `PhotosTransport` contract from the concrete authenticated HTTP client, and owns credentials, TOTP login, timeline/page requests, thumbnails, original-photo downloads, and ranged video requests. `PhotoCache` owns semantic resource keys, cached-first request coordination, SQLite metadata storage, compressed media files, and eviction. `SynoTimelineApp` is the SwiftUI macOS executable module; its product executable remains `SynoTimeline`.

`CachedPhotosRepository` depends on one `PhotosTransport` contract for login, collection-aware timelines and pages, Personal Space album listing and scanning, favorite and rotation writes, thumbnail regeneration/upload, thumbnails, originals, and video byte ranges. The Synology client rejects initial Favorites requests and all album requests through the timeline endpoint because those collections use different endpoints.

The repository remains the sole coordination actor and caller-facing interface. `RepositoryAuthenticationState` owns login attempts and replayed status; `MetadataEngineState` owns source reconciliation, collection epochs, catalogs, page/detail jobs, inventory coverage, and observers; `RepositoryImageWork` owns shared thumbnail, original, and video-segment jobs; `RepositoryFavoriteState` owns optimistic favorite overrides; and `RepositoryItemMutationState` publishes authoritative/optimistic item replacements. Actor-isolated extensions contain authentication, metadata, media, Favorites, and rotation pipelines. They retain the same suspension points and distinct transfer policies, so mutation ordering, cache-generation checks, subscriber cancellation, and priority promotion remain ordered on the shared actor.

All metadata uses one repository-owned engine and the existing `DiskCache` SQLite actor. `MetadataWorkToken` captures repository admission, storage generations, job identity, and relevant mutation epochs. SQL admissions additionally compare the central revision/reset epoch. Transactions never suspend. The sole source reader uses observed Diff v7 `get_version`/`list`: a terminal interval of at most 2,000 total changed IDs (modifications plus deletions) and a 4 MiB response may advance the central cursor atomically with canonical replacements, deletions, and dependent invalidation. Modified IDs are looked up in batches of 100 and fenced. Empty intervals commit only the cursor; small intervals query only affected old ID/time rows. Partial, oversized, malformed, unsupported, or rejected cursors centrally invalidate coverage and fall back to authoritative reads. Authentication/offline errors retain cached content without rebuild loops. Favorite/album membership and favorite annotations remain authoritative per run; an empty item feed cannot validate them. No feature owns a Diff cursor.

`CollectionDayCatalog` validates packed/split NAS Timeline sections into unique capture-local days and counts. `CollectionDayPager` emits one day per logical section with capacity 250. `DayPageAddress` includes collection, day, day-local offset, capacity and order; it excludes section index, current count and global fingerprint. Catalog presentation revisions and per-day membership generations are independent: inserting an unrelated day preserves older slots, while changes within a day conservatively invalidate all its membership. Album enumeration yields the same catalog and ordered identity/time membership inside the engine.

The normalized tables separate `item_index` identity/time/GPS projection, `item_details` canonical full content and annotation authority, collection catalogs/day generations, exact ordered `day_pages` membership, indexed `page_items` reverse references, and album summaries. Detail eviction leaves every known ID and ordinal intact. `PhotoPageSnapshot` carries membership verification and exact optional item slots; individual slot verification governs media/actions, and aggregate verification requires complete current details. Shared ID acquisition serves sparse repair, Map and Library filters in batches of 100. Cold pages use one combined full-field request. `MetadataReadPlanner` batches up to 1,000 contiguous demanded items across at most 32 populated days, with no undemanded gap padding and two physical network slots. Coverage mismatch joins one collection recovery/catalog refresh and receives one retry. Superseded metadata formats are discarded without decoding or migration; media values/bytes retain their existing format.

At startup the app reads required `USER` and `PW` plus optional TOTP secret `OTP` from the ignored `.env`. Missing or blank `OTP` omits `otp_code` from login; a NAS two-factor requirement produces a configuration error immediately. Configured OTP accounts retain the bounded fresh-window retry. Login uses the observed web-client `webui` session; the arbitrary `SynologyPhotos` session was rejected for a normal account despite working DSM/Photos web access. It opens one shared repository for the app process and starts cached-first Personal Library and Favorites timeline loads concurrently. Personal Library may use `get_init_timeline` on a cold cache before full `get`; Favorites always uses full `get` with `favorite_only=true`. The Personal Space album list is loaded only after the Albums destination is selected, and each album timeline is loaded only after that album has been opened. Album timelines are synthesized from a capture-time-descending item scan because `Browse.Timeline` ignores `album_id`. Identical startup descriptors update verification state without replacing the viewport. Timelines and album metadata are not polled during the run. Successful local favorite mutations trigger a coalesced authoritative Favorites timeline refresh; pages remain demand-driven.

Normalized snapshots expose stable day-local sections to the navigator and viewport. Windows rebase by address, preserve unchanged older-day membership, and retire in-memory proofs on typed day invalidation even when counts and snapshot fingerprints are unchanged. Viewer windows retain at most three pages, browser windows at most eight; selected identity is remapped using membership proof independently of unrelated detail holes. A missing selected detail preserves its displayed image while authority is pending. External changes are reconciled on demand once per run rather than polled.

The AppKit photo-viewer canvas is layer-backed: an appearance-matched backdrop `CALayer` (white in Aqua, black in Dark Aqua) and a separate image `CALayer` hold the displayed bitmap, and the decoded `NSImage` is uploaded to the image layer's `contents` only when the displayed image identity changes. Fit, zoom, and pan geometry still come from `PhotoViewportTransform`; transitions animate only layer position, bounds, and opacity with Core Animation, so no animation frame resamples the image. Interrupted or retargeted transitions read the image layer's presentation geometry, so open, close, upgrade, and resize never jump. A persisted pixel-interpolation preference maps to the image layer's magnification/minification filters (`NSImageInterpolation.none` to nearest, otherwise linear), preserving the always/thumbnail-only/off semantics; presentation state still distinguishes a provisional thumbnail from the decoded original to choose the effective preference, and a preference change updates the open viewer immediately. Reduce Motion replaces spatial transitions with a short compositor fade, and a missing close destination fades the image layer while the backdrop clears.

`LibraryIndex` hashes the complete, ordered descriptor snapshot and maps each UTC day to exact slices of every contributing section response. Slices carry page-local, day-local, and collection-ordinal coordinates. It also maps ordinals to fixed-grid visual rows and directional destinations across day breaks. `LibraryViewportGeometry` derives exact document height and square-slot positions from descriptor counts and the 3–10 column preference before metadata loads. Retained pages add the selected presentation's interaction/image rectangle — an aspect-fitted frame, or the full square slot when square cropping is enabled — without moving slots; visible cross-page rows demand every contributing section. Distant slices retain scalar geometry, not item arrays or row views. `LibraryPageWindow` accepts visible and adjacent prefetch sections, retains at most eight pages, emits cached pages promptly, and rejects obsolete responses. The viewport reconciles retained pages after events because buffered hints may be dropped.

Each collection browser hosts an `NSScrollView` in SwiftUI beside the equal-day Canvas navigator. Its flipped document creates pass-through `NSHostingView` rows and date headings only in the visible region and a small overscan, with an AppKit overlay for selection outlines and marquee feedback. It restores scroll position by visible item ID plus pixel offset when possible, otherwise by date and slice position; explicit navigator requests jump to the date's first slice. Scrolling updates the selected date without issuing another jump. Same-day fixed rows remain stable across API slices, page arrival, and eviction; unloaded metadata leaves an exact placeholder slot. AppKit bounds notifications handle scrolling and resize, while thumbnail tasks end as row hosts leave the viewport. Image decoding is limited to two concurrent jobs separately from six thumbnail transfers. The trailing toolbar status observes replaying repository authentication status; failed sign-in remains memoized until explicit retry. Cached data remains usable while signing in or after failure.

Exact section item pages are cached and validated once per run. Timeline and page keys include the collection; thumbnails and originals remain shared. Favorites pages use `favorite_only=true`; album pages use `album_id` plus capture-time ordering. Both remain demand-driven. Items retain server order and are grouped by UTC day, matching section request bounds. `FixedPhotoGrid` supplies pure equal-slot and aspect-fit geometry. Resizing preserves the 3–10 column count; the toolbar and Library menu change it in integer steps. Slot, row, and document geometry are fixed; a persisted presentation preference selects whether each cell centers an aspect-fitted rendition or fills and clips the full square slot, and it determines the materialized interaction/image rectangle used by hit-testing, marquee, selection outlines, reveal, and viewer transitions. The cell clips at that selected visible frame, after the frame is imposed, so aspect-fill overflow cannot bleed into adjacent cells. A user-driven square/aspect-fit change animates only that visible frame between the fitted rectangle and the slot over a short ease-in-out morph, driven by one observable presentation object shared by already-retained hosted rows so their `AnyView` roots and decoded media are reused; slot, row, document, column, scroll, page-demand, and virtualization geometry stay fixed, hit-testing stays at the final target throughout, and newly materialized rows appear directly in the current mode. The AppKit selection overlay and viewer transition sources read that final interaction geometry, so outlines snap rather than morph. Reduce Motion applies the final frame immediately. The native viewport creates thumbnail cells for nearby rows. Each cell shows cached bytes first and validates/downloads after current page metadata arrives, reusing already decoded bytes across a presentation change. A displayed rendition remains visible while it is validated. Six thumbnail transfers and two metadata requests can run concurrently. Pending queues are bounded, with visible demand before prefetch. Shared repository jobs cancel when their last subscriber leaves; cached reads do not wait for login or a network slot. ImageIO downsamples off the main actor; an `NSCache` limits retained decoded images.

Personal Library filtering is a session-derived collection layered over those authoritative pages. After a validated Personal Library timeline arrives, `LibraryFilterController` reads every page key addressable by that snapshot through the repository's network-disabled cached path, with at most two reads active. Before discovery starts, it subscribes to repository page commits for the exact source descriptors. Coalesced wakeups drain a per-observer set bounded by the captured timeline, so dropped hints cannot lose page updates and no photo payloads accumulate in the notification stream. New commits from any consumer trigger bounded cache-only reads; applying a filter also reconciles disk coverage. Shutdown and metadata reset detach observers. It retains compact scalar records for sparse source coverage after ordinary page-window eviction; one canonical `(source section, page offset)` sequence, with item-ID deduplication, drives both normalized facet catalogs and filtered registrations. Current-run verified replacements supersede provisional cache records, while late provisional emissions cannot downgrade them. Synthetic days may therefore expand as noncontiguous sections arrive. The browser maps visible synthetic sections back to source sections and sends direction-specific user-scroll demands near either edge. One gesture generation admits at most eight new source sections into an ordered deduplicated queue, and the queue performs at most two cached-first page reads concurrently; passive snapshot rebuilds do not advance it. Empty results use an explicit bounded initial batch because they have no viewport anchor. A `.libraryFilter(UUID)` registration retains exact ordered IDs and source references for eligibility. Its sparse page materialization uses shared canonical ID details, rechecking registration, source fingerprint, reset epoch, identity/day and predicate after awaits. Derived collections have no parallel array cache or source-page fanout. Canonical detail commits route bounded reverse-reference hints to filter indexing. Favorite and field-scoped rotation broadcasts update visible derived slots.

`TimelineSectionCacheLoader` warms every persistent collection through the same engine. Discovery includes unopened normal Personal albums. Its bounded 64-page logical lookahead allows tiny days to share transport batches while the engine retains the two-request network limit. Complete cached pages may be skipped with **Use Cached Pages**; sparse or missing pages acquire only the needed details or combined membership/details. The default forces authoritative membership. Cancellation stops demand admission and releases shared subscriptions; explicit retry retains the original cache policy. Map inventory remains a separate demand on the same engine.

SQLite holds normalized metadata and cache bookkeeping. Compressed image bytes and video segments live in hashed files under an account-scoped directory inside the repository's ignored `.cache/` directory. `CacheLocation` finds the repository containing `Package.swift`, because Finder and LaunchServices do not provide a dependable process working directory. The SQLite index has an explicit schema version; incompatible or unreadable indexes and their media files are recreated from NAS data. The index records validation run, access time, ETag, Last-Modified, content digest, and a monotonic row revision. Settings offers full clear and metadata-only clear. Metadata-only clear advances its storage generation at admission, transactionally removes metadata rows, broadcasts only a successful invalidation revision, and preserves compressed/decoded media data and already admitted transfers. Full clear also advances the whole-cache generation, removes media rows/files, and cancels media work. Every normalized write enforces the shared budget after commit. Disk trimming removes video segments first, then optional viewer previews, full images, thumbnails, canonical details/membership, compact inventory, and finally catalog metadata. Compact index eviction clears persisted inventory completeness; details leave sparse slots. Preview and ordinary `xl` thumbnails share a key and file; ordinary demand promotes only the entry category, and preview work cannot demote it. The configured budget and media preferences are in Settings. Budget usage currently counts indexed payload bytes; SQLite/WAL overhead and temporary writes are not included in the displayed figure.

The current certificate mismatch is accepted only for the configured Cirrus host. The app's transport-security exception and the URL session trust override are both scoped to that hostname. The URL session uses ephemeral cookie storage, and credentials, OTP values, session IDs, and tokens are never logged. `.env` is a development credential source; a distributable app should move credentials to Keychain.

Unified diagnostics use the stable `local.cirrus.syno-timeline` subsystem with separate viewer asset, original repository/transport, video player/repository/transport, rotation repository/transport, and viewer decoding categories. Video diagnostics record requested/effective quality, metadata/network authorization, cache decisions, byte ranges, response status and timing, AVPlayer state and waiting reason, and sanitized error domain/code. Rotation diagnostics record the item/unit identity, stage, rendition byte counts, response status, Synology error code, revision-poll result, and recovery outcome. Diagnostics exclude filenames, cache keys, credentials, tokens, session IDs, cookies, authenticated URLs, and response bodies. `make debug` opens Console normally and then runs the app in the foreground; the reusable Console subsystem search is `s:local.cirrus.syno-timeline`.

The application shell reuses one virtualized browser for Personal Library, Favorites, opened albums, and session map filters beneath an optional full-window AppKit photo canvas or native video player. A standard `NavigationSplitView` sidebar contains Library plus Favorites, Map, and Albums destinations. Albums opens a full-detail overview grid; opening a card enters the shared browser with a back control and the album name in the toolbar. Map opens a clustered overview; opening a pin or cluster enters the shared browser with a Map back control. The system owns sidebar resizing and toggle placement, and changing destinations closes the viewer. The native unified toolbar overlays detail content, which passes beneath a Liquid Glass top surface spanning the detail column. The viewer fits below the toolbar; magnified photos may extend behind it. The toolbar switches from the discrete items-per-row control to media-specific controls, filename, capture-local date, and loading status while viewing. While a shared collection browser is visible, the toolbar also carries a button beside the items-per-row control that toggles the persisted square-crop thumbnail presentation, mirroring the Library menu command. System appearance drives semantic colors in SwiftUI and the hosted AppKit viewport. The app requires macOS 27 and uses native Liquid Glass. Grid column count changes independently of the thumbnail rendition selected in Settings. Browser content carries a small horizontal edge inset derived from the grid gap. A compact trailing navigator appears near the pointer, while dragging, or with keyboard focus; its reserved width stays fixed to avoid hover-driven grid reflow, and a persisted option can keep it visible while idle.

The app persists one concrete version-3 navigation payload in user defaults: the selected sidebar destination, the last opened album ID, and a dictionary of optional timeline anchors keyed by persistent collection identity. Timeline anchors identify a photo by server item ID and retain an ISO day fallback, layout-relative offset, and server page-offset hint. Restoration first opens the nearest available day, then refines to the photo after its hinted page loads. A restored album ID is cleared only after a verified album list shows that it no longer exists. Session map filters are deliberately not persisted. Corrupt payloads and any schema version other than the current one are discarded completely.

`BrowserScrollIntentCoordinator` owns a single typed restoration, viewport-preservation, viewer-reveal, or selection-navigation intent. New day jumps, selection moves, and viewer requests replace earlier intent; user scrolling cancels pending refinement. Descriptor rebuilds rebase the active intent, while verified page progress survives page eviction until restoration settles. Saved anchors preserve their pixel offset; viewer reveals center the photo and bind deferred rectangle completion to the request identity. The AppKit adapter applies scroll effects and retains responsibility for bounded page demand and row hosting.

## Full-size image resources and navigation

`PhotoViewerSession` navigates an immutable `LibraryIndex` using section-prefix counts and exact page offsets, including thumbnails carried into rows across API page boundaries. It retains at most three metadata pages and the current plus two adjacent encoded originals. Replaying snapshots carry a selection generation; request tokens and generation checks reject obsolete results during rapid navigation. Verified metadata preserves the selected item by ID if its page position changes. Provisional metadata may read cached images but cannot authorize image downloads. The session privately observes successful metadata invalidations, releases discarded metadata/navigation work, and exposes an ordinary reopen state while the presentation keeps its already decoded image until the shell closes the obsolete context.

The session remains the sole actor for viewer coordination. Its `ViewerMetadataWindow` value owns ordinal lookup and bounded page/job retention; `ViewerImageWork` owns encoded bytes, image tasks, and shared cancellation/reset operations. Selection changes adopt a retained decoded configured thumbnail for the new item when one exists; otherwise they clear displayed bytes. Retries preserve them, and closing cancels all viewer image work. Actor-isolated extensions separate metadata reconciliation, current asset loading, adjacent prefetch, and Favorites mutations without introducing additional actor hops.

The original-photo repository uses separately keyed compressed files and conditional validation once per run. Two transfer slots allow at most one speculative request, leaving capacity for visible demand. Selecting an in-flight neighbor promotes its shared job instead of downloading it again. Leaving an image cancels obsolete work; neighboring images are requested only after the current image succeeds. Cached bytes remain usable if validation fails.

When “Load large previews in viewer” is enabled and the configured library rendition is smaller than `xl`, the viewer displays and fetches the configured thumbnail immediately, while cached `xl` previews and originals are also read immediately. Network-backed `xl` and original requests wait for the selection to remain stable for 100 ms, then start concurrently and warm one adjacent `xl` thumbnail in each direction. This avoids expensive transfers for intermediate selections during key repeat. These requests use the shared thumbnail pipeline but write the lowest-retention preview category. The viewer accepts an `xl` upgrade and retains it if original transfer or decoding fails; a successfully decoded original remains final. Configured thumbnail bytes for the current item and up to two items in each direction are retained in memory; the presentation decodes them before navigation needs them and installs the decoded neighbor image in the canvas with the new selection, so cached navigation never shows a blank or loading frame. Adjacent `xl` previews are also decoded for the two offscreen viewer layers when available; originals retain compressed bytes only, and obsolete work is cancelled. If the configured rendition is already `xl`, its cached data is still read immediately and its network request uses the same stability delay; the separate preview category is inactive and ordinary thumbnail demand transparently promotes any matching preview entry without copying or downloading it again.

Thumbnail activation supplies the displayed image and an AppKit window-coordinate source rectangle for the expansion transition. The viewer keeps its image and zoom state per window; arrows change the desired selection and issue bounded background reveal requests to the browser. A pre-decoded adjacent thumbnail is installed directly into the canvas's image layer when the selection generation changes, so no frame is drawn without the next photo. At fit zoom a horizontal two-finger swipe is direction-locked after a small dead zone and moves the current image and the corresponding prepared neighbor layer in lockstep. Three reusable layers represent previous, current, and next; a committed swipe promotes the incoming layer itself and recycles the outgoing layer, avoiding a visible layer handoff. Release commits by displacement or horizontal velocity: the canvas asks the presentation to navigate, and the new selection's generation confirms the page by item ID so the in-flight slide finalizes without resetting or blanking. The layers retain their spacing during a smooth settling animation, and a new gesture can interrupt a confirmed settle from its presented position. Below the threshold the two layers spring back. Back/Escape resolves the current item's live cell rectangle and collapses into it, with a timed fade fallback when no live destination exists. A fit-zoom downward two-finger swipe is handled entirely inside the canvas: precise scroll events are direction-locked after a small dead zone, drive the photo's translation/scale and the independent backdrop fade, and on release either spring back to the fit frame or fire a single interactive-dismiss callback. `AppShellView` runs that callback through the same close pipeline as Back/Escape — `PhotoViewerPresentation.close()`, the current item's `BrowserRevealRequest`/`LibraryBrowserBridge` destination, then `canvasController.collapse` from the held dragged state — so the viewer and session stay alive during the gesture and cleanup happens once after the visual finishes. Above fit zoom precise scrolling always pans and never dismisses or pages; Reduce Motion and videos never offer the spatial gestures. A changed authoritative timeline snapshot invalidates ordinary navigation with an explicit reopen message, while local Favorites refreshes leave the open session playlist intact. Preview and original upgrades share the current transform.

The executable separates viewer source anchors, window chrome measurement, presentation and decoding, SwiftUI overlays, the canvas bridge, and AppKit canvas input and animation into individual files. The canvas fills the split view's detail width and reserves the measured toolbar height when fitting an image. It drives transitions from a single internal phase (resting, opening, interactive dismissal, awaiting destination, interactive paging, paging commit, awaiting page, paging return, returning, closing) rather than overlapping flags, and owns the precise-scroll direction lock and velocity tracking for the dismissal and paging gestures.

Personal Space item pages include optional `additional.favorite`; omission means the item is not favorited. The viewer requires verified item metadata before enabling its heart toolbar button or the Library menu's `.` command. `SYNO.Foto.Browse.Item.set_favorite` writes are serialized by the shared repository and remain active if the viewer closes. The viewer tracks pending writes and errors by item ID, so navigating away does not disable the heart for another photo. Before awaiting the NAS, the repository broadcasts a pending presentation overlay. Confirmed chunks patch only the canonical favorite field; failed/unsubmitted IDs remove their overlays, leaving persisted authoritative content intact. Favorites catalog/membership is invalidated before refresh, including equal-count changes. Stale admitted page writes cannot overwrite newer confirmed fields. The viewer preserves its opening Favorites playlist while its membership changes.

The browser reuses the same favorite pipeline for selections. The Library menu's `.` command and a persistent toolbar heart route to the active viewer or to the active browser selection. `SelectionFavoriteResolver` maps selected ordinals to `LibraryIndex` locations, reads only the sections that contain them (at most two pages concurrently, waiting for verified metadata), and aborts if the index fingerprint or a previously known item identity changed. A mixed selection favorites only its unfavorited items; an all-favorite selection unfavorites them all, and the affected count (not the selection count) drives a window-modal confirmation above five items. `SelectionFavoriteAction` carries the resolved IDs, one target value, source sections, and item metadata. `setFavoritesBatch` atomically claims every ID against the pending set, publishes one batched overlay, then writes fixed-size chunks in order and patches confirmed canonical fields; on a chunk failure it keeps completed chunks, rolls back only the failed and unsubmitted IDs, and schedules one coalesced authoritative Favorites refresh. The single-item viewer path remains a wrapper over the same batch entry point.

`SelectionRotationResolver` uses the same bounded verified-page pattern for still-image rotation and omits unsupported videos. Normal rotation publishes an optimistic quarter-turn presentation, sends `Browse.Item.set`, then applies field-scoped authoritative rotation/thumbnail values to canonical details and the compact projection; failure restores presentation state. Concurrent favorite and unrelated metadata fields are preserved. The viewer also rotates its currently displayed bitmap immediately. ImageIO applies the unchanged original file's EXIF orientation during full-image decoding; the viewer then applies only the quarter-turn delta from `orientation_original` to Synology's current `orientation`. Server-generated thumbnail bytes receive no second orientation transform. The native Edit menu owns icon-labeled left/right commands for normal and thumbnail-only rotation plus automatic thumbnail repair; only normal rotation is also exposed in the toolbar. Thumbnail-only rotation is a separate cancellable repository stream: one item at a time downloads all three ready renditions, rotates JPEG bytes locally, calls `set_regenerating`, uploads the multipart converted files, polls a bounded number of times for the new cache key, and publishes the refreshed item. Automatic repair first obtains the original through the shared full-image cache and uses a separate ImageIO analyzer actor to create bounded, orientation-normalized luminance rasters. It evaluates four relative quarter turns per rendition using normalized luminance and edge correlation with aspect, absolute-score, and runner-up-margin gates. `sm`, `m`, and `xl` must each be confident and unanimously select the same turn before `set_regenerating`; a unanimous zero-turn result performs no write, and missing, undecodable, ambiguous, or disagreeing input fails before server mutation. Every ambiguous regeneration/upload failure or cancellation performs detached `restore_from_regenerating` cleanup and a cancellation-independent bounded authoritative reread, adopting any advanced cache key before reporting failure. The transport exposes byte progress for original downloads and multipart uploads; request timeouts are inactivity limits while the resource timeout is a generous absolute cap. Full originals use an explicit `URLSessionDataDelegate` that accumulates the body and publishes every delivered data chunk instead of relying on a buffered convenience download. The modal maps each current photo's downloads to 0–1/2, local analysis/encoding to 1/2–2/3, and upload to 2/3–1. The download aggregate estimates `sm` at 60 KB, `m` at 150 KB, and `xl` at 1 MB, adds the original's metadata filesize (or a 5 MB fallback), and replaces the original estimate with HTTP expected bytes once available. The status names the active rendition, live original bytes update the fraction, and SwiftUI animates between callbacks. A bounded-height scroll view shows only the final outcome for each photo.

The app hosts a floating Info utility window toggled by the Library menu's Cmd+I command or the toolbar info button beside the favorite control. `InfoPanelModel` publishes a synchronous count and day-range summary for a multi-item browser selection, then runs a 150 ms-debounced `SelectionInfoResolver` for the exact cumulative size and photo/video counts; the resolver reads only timeline sections containing selected ordinals, at most two concurrently, cancels superseded generations, and leaves the size unavailable when a section fails or any selected item lacks a filesize. The panel always shows the viewer's current item while the viewer is open, shows a placeholder when nothing is selected, and performs no page reads while hidden. Item pages bundle `exif` and the slash-prefixed Personal Space `folder` path with the existing `additional` fields, so single-item camera details and a copyable path are available from canonical full-detail rows. Single-item filename and item ID are also individually copyable, while identity details are omitted for multiple selections. The utility window is transient, ignores the window cycle, and keeps only its close button enabled; closing the main window dismisses it.

Synology's `PhotoItem.time` is a capture-local wall clock encoded as epoch-shaped seconds, not an absolute instant. Timeline grouping and UI formatting both use GMT calendar components so a photo taken at 21:00 displays 21:00 regardless of the Mac's current timezone. No timezone is inferred from location or device state. Favorites is treated as a filter over the same stable chronological item order: removing and re-adding membership does not redefine an item's ordering key.

`FullImageDecoder` performs orientation-aware ImageIO decoding away from the main actor. It preserves original pixel dimensions, admits one decode and one replaceable waiting request, and rejects images above a 384 MB decoded-image limit with an explicit error. Neighbor original prefetch retains compressed data only; neighbor thumbnails and optional large previews may also be decoded. `PhotoViewportTransform` computes fit, pointer-anchored magnification, and bounded pan in canvas coordinates, independently of the interface. `PhotoViewerDismissal` computes the interactive dismissal's direction lock, bounded translation/scale/backdrop response, and distance/velocity commit decision, independently of AppKit.

The optional viewer filmstrip extends the existing bounded metadata and thumbnail window to ten items on each side, retaining at most three metadata pages; an AppKit divider changes thumbnail size and therefore visible count. It reuses the browser thumbnail aspect geometry and badge overlay. The histogram stores its luminance or RGB display choice in app preferences, samples both modes from a 256×256 raster off the main actor, stays below the toolbar, follows the drag in a fixed coordinate space, and animates on release to the corner selected by the projected endpoint. It follows backdrop opacity during dismissal; Reduce Motion disables the snap animation. `ViewerGPUImageRenderer` owns a reusable Metal/Core Image pipeline: it color-converts and resamples the displayed image in floating-point extended sRGB to at most ten megapixels, executes an effect-owned shader, and reads back an overlay of at most 2048 pixels on its longest side. `ViewerGPUImageEffect` contains each effect’s shader and argument binding; `HighlightPeakingEffect` classifies up to four samples per overlay pixel using the configured peak-component threshold and an HSV saturation limit of 5%, and overlay alpha represents their coverage. Eight-bit inputs use a 16-bit float intermediate with up to ten million samples; higher-depth inputs use 32-bit floats with up to four million samples. Effect shaders compile once on first use. GPU requests are serialized, cancelled work is discarded before dispatch or publication, and a submitted command finishes before the next request starts. The 5% neutral-color tolerance is a heuristic, not a scientific clipping standard. This bounded approximation indicates rendered near-white highlights, not raw sensor clipping, and can miss or blend away smaller source details during resampling. [OpenCV’s HSV definition](https://docs.opencv.org/5.0.0-alpha/de/d25/imgproc_color_conversions.html) defines value as the largest RGB component and saturation as the relative channel spread; [NVIDIA’s sampling discussion](https://developer.nvidia.com/gpugems/gpugems2/part-iii-high-quality-rendering/chapter-21-high-quality-antialiased-rasterization) describes reducing multiple samples to coverage. [RawTherapee](https://rawpedia.rawtherapee.com/Clipping_Indication) distinguishes all-channel clipping from any-channel clipping, and [darktable](https://docs.darktable.org/usermanual/4.2/en/module-reference/utility-modules/darkroom/raw-overexposed/) distinguishes raw clipping warnings from rendered-image analysis. Threshold and image changes cancel and replace the current calculation; the prior overlay remains visible for the same selection until a replacement is ready. Image-relative overlay containers are attached to the current and neighboring image layers; their geometry changes without implicit animation, and spatial transitions scale each whole layer so overlays follow image geometry. Neighbor metadata supplies Live Photo indicators before interactive paging begins, and promotion preserves the incoming indicator. Selection changes hide old overlays, and cancelled work cannot publish stale results.

## Video playback

Item pages decode the observed `video_convert` array and its `mobile`, `low`, `medium`, `high`, and `orig_h264` quality identifiers. `VideoQualityPreference` is a semantic user preference rather than a wire value. Automatic targets High. Resolution considers only known qualities advertised by the current item, minimizes ladder distance, and orders an equal-distance lower rendition before a higher one. Original is a separate stored-file variant; it is also the fallback when no converted rendition is advertised. Resource keys include account namespace, thumbnail cache revision, effective variant, and segment index.

`SynologyClient.videoRange` uses authenticated `SYNO.Foto.Streaming` v2 requests for converted variants and `SYNO.Foto.Download` v2 for stored originals. Both paths require a valid `206` response, matching `Content-Range`, media content type, and exact payload size. The repository aligns demand into 64 KiB segments, coalesces identical segment jobs, limits video to a separate two-transfer lane, and assembles only the caller's requested bytes. The deliberately small segment is the atomic buffered `URLSession.data(for:)` response: it lets a slow NAS/link return incremental ranges to AVFoundation before its resource-loader stall window expires. Video segments share the main disk budget, rank below every photo rendition for eviction, survive metadata-only clear, and are removed by full clear. There is no adjacent-video prefetch. Current item metadata must be verified before the player may start a new network range; cached ranges remain readable without network authorization.

`VideoPlayerContainerView` wraps `AVPlayerView` and gives `AVURLAsset` an opaque custom-scheme URL. `VideoAssetLoader` translates AVFoundation content-information and byte-range loading requests into repository calls without exposing credentials or authenticated NAS URLs. The existing thumbnail remains over the video surface and beneath native controls until the first frame is ready. The canvas keeps the active player synchronized with the current visual slot through interactive transitions, retaining the outgoing player until the slide completes; neighboring videos use only their thumbnails. Replacing or dismantling the view pauses the player, cancels loader tasks, and releases the asset; its identity includes the viewer selection generation and effective rendition so stale work cannot be reused for another item. Native controls own seeking and play/pause; precise trackpad scrolling over video is routed to the canvas for the same paging and dismissal gestures as photos.

Live Photo playback waits until the full still is displayed and its metadata is verified. An indicator click or Force Touch press performs an authenticated `SYNO.Foto.Browse.Unit` v1 `get` for that item, selects the single video member and its advertised converted rendition closest to High, then streams it through the same range cache and loader as ordinary video. An image-relative Live Photo indicator changes to an animated loading symbol through member lookup and first-frame buffering. The controls-free player sits over the still and is removed at the end of playback, on Force Touch release, drag, selection change, or viewer closure; lookup is cancelled and fenced by selection generation. A normal hold does not start motion. The still remains visible if lookup or playback fails. Motion is suppressed when Synology display orientation differs from the original, matching the web client and avoiding a mismatched rotated still. Member descriptors are fetched on demand and are not persisted, so motion lookup needs a network connection even when video ranges are cached.

## Locations and map

`Browse.Item.list` pages can carry an optional `additional.gps` object. `PhotosRequestFields.pageAdditional` includes `gps`, so every page (normal, album, and filtered) exposes `PhotoItem.coordinate` and the info panel can show location context without a separate request. Items without a location omit the key.

Map reads its compact projection from the shared `item_index`. Cached pins remain visible as unverified when validation fails. A complete inventory includes located and unlocated IDs; row profile/epoch and persisted completeness jointly gate authority. Cold or invalid coverage triggers one shared engine-owned inventory scan, with a freshly reconciled central boundary immediately before scanning, 1,000-row scoped reads, staged uniqueness/per-day counts, and a terminal fence. Races fail conservatively. Inventory state plus projection are read atomically before publication, including after automatic trim. The shared finite scan may continue after observers leave. Ordinary page/detail work publishes changed-ID updates only when Map observers or derived dependencies need them; coalesced presentation avoids decoding the full inventory after each page.

`MapClusterBuilder` (`TimelineCore`) is a deterministic, grid-accelerated radius clusterer: it visits records newest-first and joins each to the nearest open cluster whose newest member is within one radius on both axes, otherwise opening a new cluster. Two nearby photos therefore never split just because a grid boundary falls between them, and clusters never chain arbitrarily far. The radius starts at the finest useful value (viewport span / 512, raised to the viewport's on-screen pin pitch) and doubles until the cluster count fits 64 annotations, so low zoom shows counted clusters, medium zoom splits them, and a lone photo renders a single thumbnail pin. Records sharing an identical coordinate stay clustered at every zoom; the antimeridian is not handled. `MapBrowserModel` derives the radius from the current camera region and view size, reclusters off the main actor with a ~120 ms debounce after camera changes or window resizes, cancels obsolete workers, fits the camera once to the records' bounding region, and keeps an ID-to-index map so opening a pin or cluster resolves its member records in O(members).

Opening a pin or cluster passes selected IDs and an opaque location revision to the repository. After validating membership, it registers a session-only `.mapFilter(UUID)` collection with the common day pager. Sparse slots materialize directly from shared canonical details, with batched ID acquisition for missing/current details and registration/revision checks after suspension. There is no covering-Personal-page fanout or derived array cache. Projection changes invalidate dependent registrations through typed events and return the shell to its preserved Map camera. Session filters are never restored after launch.

The info panel appends a small `Map(position:)` below the metrics for a single located item or below the size row for a multi-selection, with one `Marker` per located photo. Its bound camera refits whenever the pins change, including after a manual pan or zoom. MapKit automatically frames distinct locations to the viewport; a single location or colocated pins use a local 0.01-degree region. The map is omitted entirely when none of the involved photos has a location.

## Geometry and input

Each populated day owns the same fraction of the usable track. Empty days occupy no space. Item counts do not influence spacing.

For `N` dates, track origin `top`, track height `H`, and pointer `y`:

```text
fraction = clamp((y - top) / H, 0, 1)
dayIndex = min(N - 1, floor(fraction * N))
markerY = top + H * (dayIndex + 0.5) / N
```

This gives constant-time pointer lookup. A single `Canvas` paints the track, month marks, year labels, and selection indicator. One transparent rectangular view handles continuous hover and click/drag input. There are no per-day views or hit targets. Year labels are culled when less than 25 points apart, without changing the underlying date geometry.

More populated days than screen pixels necessarily means some days cannot be individually targeted with the pointer. Arrow keys and the accessibility adjustable action allow exact single-day stepping. Hover feedback includes both year/month and the exact selected calendar day.

## Selection contract

`TimelineNavigator` exposes a selected day index through a binding. In Personal Library, user input creates a jump request with a fresh identity, including a repeated selection of the same date. Browser scroll feedback updates the bound selection without creating a jump. Date selection survives a changed index by using the nearest remaining older day. A section can contain several days, so the browser resolves the exact day slice before scrolling.

Each browser collection keeps a session-local `LibrarySelection` as normalized ordinal ranges. Pointer clicks replace or add one item; Shift-Option-click adds the inclusive range from the nearest already-selected ordinal, with the earlier ordinal winning an equal-distance tie. Marquee selection replaces from current hits, while Shift-marquee applies symmetric difference against the gesture-start baseline. Cmd+A selects the collection's full ordinal range without materializing item metadata. Directional commands choose the earliest border for Left/Up and latest border for Right/Down. Shift commands retain the gesture-start selection, a fixed border, and a movable cursor; the active inclusive reading-order range grows or shrinks as the cursor moves without removing baseline items. Page verification compares ordered item-ID signatures and invalidates ordinal selection if membership or order changed. Selection survives row recycling, scrolling, sizing changes, and destination switching without materializing metadata for every selected ordinal. The key window's AppKit browser responder dispatches the same commands defined in the Library menu; sidebar, navigator, viewer, Settings, and other-window focus do not invoke browser selection. Selection mutations continue to resolve verified metadata before presenting or executing an action; actions on the entire collection always require confirmation, while other favorite changes retain the affected-count threshold.

Location labels remain deferred.

## Cache direction

`ThumbnailRangeDownloader` handles explicit range downloads from the Library menu. The nonmodal picker maps its two handles to oldest-to-newest populated dates and sums the selected distinct-day item counts. It uses a validated snapshot, resolves every contributing section (including split days), and filters each page to the selected day slices. One metadata page and two low-priority thumbnail workers are processed at a time; no whole-library photo array or decoded images are retained. It shares the repository's jobs and cache with browsing. Progress distinguishes fetched, reused, unavailable renditions and errors; successful processing does not pin entries or override the cache budget. Closing the download window cancels its work.

Typed finite `AsyncStream` results emit cached values first and current values after validation, then finish. Thumbnail GETs use `If-None-Match` or `If-Modified-Since` when cached validators exist, and accept 304 only with local bytes. The NAS remains authoritative; cached metadata is provisional until validated. See [transferred cache plan](https://github.com/finia2NA/syno/issues/28#issuecomment-6478636441) for evidence, current limitations, and future work.

The cache-location rationale and requirements for any future return to macOS's purgeable Caches directory are recorded in [decision 001](decisions/001-development-cache-location.md).
