# Personal Space browser

## Current implementation

`TimelineCore` contains the platform-independent navigator model. `SynologyAPI` separates wire/domain models and the `PhotosTransport` contract from the concrete authenticated HTTP client, and owns credentials, TOTP login, timeline/page requests, thumbnails, and original-photo downloads. `PhotoCache` owns semantic resource keys, cached-first request coordination, SQLite metadata storage, compressed image files, and eviction. `SynoTimelineApp` is the SwiftUI macOS executable module; its product executable remains `SynoTimeline`.

`CachedPhotosRepository` depends on one complete `PhotosTransport` contract for login, collection-aware timelines and pages, favorite writes, thumbnails, and originals. Transports implement every operation explicitly; the Synology client rejects an initial Favorites timeline request because the server does not support that endpoint.

The repository remains the sole coordination actor and caller-facing interface. `RepositoryAuthenticationState` owns login attempts and replayed status; `RepositoryMetadataWork` owns collection epochs, timeline/page jobs, and refresh observers; `RepositoryImageWork` owns shared thumbnail/original jobs; `RepositoryFavoriteState` owns optimistic overrides, mutation tasks, and change publication. Actor-isolated extensions contain authentication, metadata, thumbnail, original, and Favorites pipelines. They retain the same suspension points and distinct transfer policies, so mutation epochs, cache-generation checks, subscriber cancellation, and priority promotion remain ordered on the shared actor. Synchronous state helpers handle status transitions and favorite publication without additional actor hops.

At startup the app reads `USER`, `PW`, and the TOTP secret `OTP` from the ignored `.env`. It opens one shared repository for the app process and starts cached-first Personal Library and Favorites timeline loads concurrently. Personal Library may use `get_init_timeline` on a cold cache before full `get`; Favorites always uses full `get` with `favorite_only=true`. Identical startup descriptors update verification state without replacing the viewport. Timelines are not polled during the run. Successful local favorite mutations trigger a coalesced authoritative Favorites timeline refresh; pages remain demand-driven.

The snapshot preserves every section's date list, offset, and limit, while the navigator deduplicates calendar dates, retains the earliest section index for split days, and sorts newest first. It precomputes year/month boundaries once. Selection is restored by calendar date when a refreshed map arrives. Live changes during a run remain out of scope.

`LibraryIndex` hashes the complete, ordered descriptor snapshot and maps each UTC day to exact slices of every contributing section response. Slices carry page-local, day-local, and collection-ordinal coordinates. It also maps ordinals to fixed-grid visual rows and directional destinations across day breaks. `LibraryViewportGeometry` derives exact document height and square-slot positions from descriptor counts and the 3–10 column preference before metadata loads. Retained pages add aspect-fitted image rectangles without moving slots; visible cross-page rows demand every contributing section. Distant slices retain scalar geometry, not item arrays or row views. `LibraryPageWindow` accepts visible and adjacent prefetch sections, retains at most eight pages, emits cached pages promptly, and rejects obsolete responses. The viewport reconciles retained pages after events because buffered hints may be dropped.

Personal Library hosts an `NSScrollView` in SwiftUI beside the equal-day Canvas navigator. Its flipped document creates pass-through `NSHostingView` rows and date headings only in the visible region and a small overscan, with an AppKit overlay for selection outlines and marquee feedback. It restores scroll position by visible item ID plus pixel offset when possible, otherwise by date and slice position; explicit navigator requests jump to the date's first slice. Scrolling updates the selected date without issuing another jump. Same-day fixed rows remain stable across API slices, page arrival, and eviction; unloaded metadata leaves an exact placeholder slot. AppKit bounds notifications handle scrolling and resize, while thumbnail tasks end as row hosts leave the viewport. Image decoding is limited to two concurrent jobs separately from six thumbnail transfers. The trailing toolbar status observes replaying repository authentication status; failed sign-in remains memoized until explicit retry. Cached data remains usable while signing in or after failure.

Exact section item pages are cached and validated once per run. Timeline and page keys include the collection; thumbnails and originals remain shared. Favorites pages use `favorite_only=true` and remain demand-driven. Items retain server order and are grouped by UTC day, matching section request bounds. `FixedPhotoGrid` supplies pure equal-slot and aspect-fit geometry. Resizing preserves the 3–10 column count; the toolbar and Library menu change it in integer steps. The native viewport creates thumbnail cells for nearby rows. Each cell centers the rendition without cropping, shows cached bytes first, and validates/downloads after current page metadata arrives. A displayed rendition remains visible while it is validated. Six thumbnail transfers and two metadata requests can run concurrently. Pending queues are bounded, with visible demand before prefetch. Shared repository jobs cancel when their last subscriber leaves; cached reads do not wait for login or a network slot. ImageIO downsamples off the main actor; an `NSCache` limits retained decoded images.

SQLite holds timeline/page JSON and cache bookkeeping. Compressed image bytes live in hashed files under an account-scoped directory inside the repository's ignored `.cache/` directory. `CacheLocation` finds the repository containing `Package.swift`, because Finder and LaunchServices do not provide a dependable process working directory. The SQLite index has an explicit schema version; incompatible or unreadable indexes and their image files are recreated from NAS data. The index records validation run, access time, ETag, and Last-Modified. Disk trimming removes viewer-fetched `xl` previews first, then full-size images, ordinary thumbnails, pages, and finally unprotected timelines. Preview and ordinary `xl` thumbnails share a key and file; ordinary demand promotes only the entry category, and preview work cannot demote it. The configured budget and image preferences are in Settings. Budget usage currently counts indexed payload bytes; SQLite/WAL overhead and temporary writes are not included in the displayed figure.

The current certificate mismatch is accepted only for the configured Cirrus host. The app's transport-security exception and the URL session trust override are both scoped to that hostname. The URL session uses ephemeral cookie storage, and credentials, OTP values, session IDs, and tokens are never logged. `.env` is a development credential source; a distributable app should move credentials to Keychain.

The application shell reuses one virtualized browser for Personal Library and Favorites beneath an optional full-window AppKit photo canvas. A standard `NavigationSplitView` sidebar contains Personal Library plus a Collections section with Favorites; the system owns sidebar resizing and toggle placement, and changing destinations closes the viewer. The native unified toolbar overlays detail content. The viewer fits below the toolbar; magnified photos may extend behind it. The toolbar switches from the discrete items-per-row control to image zoom, filename, capture-local date, and loading status while viewing. System appearance drives semantic colors in SwiftUI and the hosted AppKit viewport. The app requires macOS 27 and uses native Liquid Glass. Grid column count changes independently of the thumbnail rendition selected in Settings. A compact trailing navigator appears near the pointer, while dragging, or with keyboard focus; its reserved width stays fixed to avoid hover-driven grid reflow.

The app persists one concrete version-2 navigation payload in user defaults: the selected collection and one optional timeline anchor for each collection. Timeline anchors identify a photo by server item ID and retain an ISO day fallback, layout-relative offset, and server page-offset hint. Restoration first opens the nearest available day, then refines to the photo after its hinted page loads. Corrupt payloads and any schema version other than the current one are discarded completely.

`BrowserScrollIntentCoordinator` owns a single typed restoration, viewport-preservation, viewer-reveal, or selection-navigation intent. New day jumps, selection moves, and viewer requests replace earlier intent; user scrolling cancels pending refinement. Descriptor rebuilds rebase the active intent, while verified page progress survives page eviction until restoration settles. Saved anchors preserve their pixel offset; viewer reveals center the photo and bind deferred rectangle completion to the request identity. The AppKit adapter applies scroll effects and retains responsibility for bounded page demand and row hosting.

## Full-size image resources and navigation

`PhotoViewerSession` navigates an immutable `LibraryIndex` using section-prefix counts and exact page offsets, including thumbnails carried into rows across API page boundaries. It retains at most three metadata pages and the current plus two adjacent encoded originals. Replaying snapshots carry a selection generation; request tokens and generation checks reject obsolete results during rapid navigation. Verified metadata preserves the selected item by ID if its page position changes. Provisional metadata may read cached images but cannot authorize image downloads.

The session remains the sole actor for viewer coordination. Its `ViewerMetadataWindow` value owns ordinal lookup and bounded page/job retention; `ViewerImageWork` owns encoded bytes, image tasks, and shared cancellation/reset operations. Selection changes clear displayed bytes, retries preserve them, and closing cancels all viewer image work. Actor-isolated extensions separate metadata reconciliation, current asset loading, adjacent prefetch, and Favorites mutations without introducing additional actor hops.

The original-photo repository uses separately keyed compressed files and conditional validation once per run. Two transfer slots allow at most one speculative request, leaving capacity for visible demand. Selecting an in-flight neighbor promotes its shared job instead of downloading it again. Leaving an image cancels obsolete work; neighboring images are requested only after the current image succeeds. Cached bytes remain usable if validation fails.

When “Load large previews in viewer” is enabled and the configured library rendition is smaller than `xl`, the viewer displays and fetches the configured thumbnail immediately, while cached `xl` previews and originals are also read immediately. Network-backed `xl` and original requests wait for the selection to remain stable for 100 ms, then start concurrently and warm one adjacent `xl` thumbnail in each direction. This avoids expensive transfers for intermediate selections during key repeat. These requests use the shared thumbnail pipeline but write the lowest-retention preview category. The viewer accepts an `xl` upgrade and retains it if original transfer or decoding fails; a successfully decoded original remains final. Adjacent previews retain compressed bytes only and obsolete work is cancelled. If the configured rendition is already `xl`, its cached data is still read immediately and its network request uses the same stability delay; the separate preview category is inactive and ordinary thumbnail demand transparently promotes any matching preview entry without copying or downloading it again.

Thumbnail activation supplies the displayed image and an AppKit window-coordinate source rectangle for the expansion transition. The viewer keeps its image and zoom state per window; arrows change the desired selection and issue bounded background reveal requests to the browser. Back/Escape resolves the current item's live cell rectangle and collapses into it, with a timed fade fallback when no live destination exists. A changed authoritative timeline snapshot invalidates ordinary navigation with an explicit reopen message, while local Favorites refreshes leave the open session playlist intact. Preview and original upgrades share the current transform.

The executable separates viewer source anchors, window chrome measurement, presentation and decoding, SwiftUI overlays, the canvas bridge, and AppKit canvas input and animation into individual files. The canvas fills the split view's detail width and reserves the measured toolbar height when fitting an image.

Personal Space item pages include optional `additional.favorite`; omission means the item is not favorited. The viewer requires verified item metadata before enabling its heart toolbar button or the Library menu's `.` command. `SYNO.Foto.Browse.Item.set_favorite` writes are serialized by the shared repository and remain active if the viewer closes. The viewer tracks pending writes and errors by item ID, so navigating away does not disable the heart for another photo. Before awaiting the NAS, the repository broadcasts the new status and patches cached Personal Library metadata. It does not fabricate Favorites membership or page order. Successful writes schedule a coalesced authoritative Favorites timeline refresh; a mutation epoch rejects older page and timeline work. Write failure restores the prior status and Personal Library cache, while refresh failure keeps the successful status and reports stale Favorites metadata. An open Favorites viewer separately records locally changed members' original day offsets and metadata. Translated, cache-bypassing page reads merge those members back into evicted pages, preserving the opening playlist with at most three resident pages until close. The timeline shows a heart badge for favorites.

Synology's `PhotoItem.time` is a capture-local wall clock encoded as epoch-shaped seconds, not an absolute instant. Timeline grouping and UI formatting both use GMT calendar components so a photo taken at 21:00 displays 21:00 regardless of the Mac's current timezone. No timezone is inferred from location or device state. Favorites is treated as a filter over the same stable chronological item order: removing and re-adding membership does not redefine an item's ordering key.

`FullImageDecoder` performs orientation-aware ImageIO decoding away from the main actor. It preserves original pixel dimensions, admits one decode and one replaceable waiting request, and rejects images above a 384 MB decoded-image limit with an explicit error. Neighbor prefetch retains compressed data only. `PhotoViewportTransform` computes fit, pointer-anchored magnification, and bounded pan in canvas coordinates, independently of the interface.

## Geometry and input

Each populated day owns the same fraction of the usable track. Empty days occupy no space. Item counts do not influence spacing.

For `N` dates, track origin `top`, track height `H`, and pointer `y`:

```text
fraction = clamp((y - top) / H, 0, 1)
dayIndex = min(N - 1, floor(fraction * N))
markerY = top + H * (dayIndex + 0.5) / N
```

This gives constant-time pointer lookup. A single `Canvas` paints the track, month marks, year labels, and selection indicator. One transparent rectangular view handles continuous hover and click/drag input. There are no per-day views or hit targets. Year labels are culled when less than 25 points apart, without changing the underlying date geometry.

More populated days than screen pixels necessarily means some days cannot be individually targeted with the pointer. Arrow keys and the accessibility adjustable action allow exact single-day stepping. Hover feedback includes both year/month and the exact selected calendar day.

## Selection contract

`TimelineNavigator` exposes a selected day index through a binding. In Personal Library, user input creates a jump request with a fresh identity, including a repeated selection of the same date. Browser scroll feedback updates the bound selection without creating a jump. Date selection survives a changed index by using the nearest remaining older day. A section can contain several days, so the browser resolves the exact day slice before scrolling.

Each browser collection keeps a session-local `LibrarySelection` as normalized ordinal ranges. Pointer clicks replace or add one item; marquee selection replaces from current hits, while Shift-marquee applies symmetric difference against the gesture-start baseline. Directional commands choose the earliest border for Left/Up and latest border for Right/Down. Shift commands retain the gesture-start selection, a fixed border, and a movable cursor; the active inclusive reading-order range grows or shrinks as the cursor moves without removing baseline items. Page verification compares ordered item-ID signatures and invalidates ordinal selection if membership or order changed. Selection survives row recycling, scrolling, sizing changes, and destination switching without materializing metadata for every selected ordinal. The key window's AppKit browser responder dispatches the same commands defined in the Library menu; sidebar, navigator, viewer, Settings, and other-window focus do not invoke browser selection.

Location labels remain deferred.

## Cache direction

`ThumbnailRangeDownloader` handles explicit range downloads from the Library menu. The nonmodal picker maps its two handles to oldest-to-newest populated dates and sums the selected distinct-day item counts. It uses a validated snapshot, resolves every contributing section (including split days), and filters each page to the selected day slices. One metadata page and two low-priority thumbnail workers are processed at a time; no whole-library photo array or decoded images are retained. It shares the repository's jobs and cache with browsing. Progress distinguishes fetched, reused, unavailable renditions and errors; successful processing does not pin entries or override the cache budget. Closing the download window cancels its work.

Typed finite `AsyncStream` results emit cached values first and current values after validation, then finish. Thumbnail GETs use `If-None-Match` or `If-Modified-Since` when cached validators exist, and accept 304 only with local bytes. The NAS remains authoritative; cached metadata is provisional until validated. See [cache plan](plans/CACHING_PLAN.md) for evidence, current limitations, and future work.

The cache-location rationale and requirements for any future return to macOS's purgeable Caches directory are recorded in [decision 001](decisions/001-development-cache-location.md).
