# Architecture

This document is the source of truth for current technical structure, subsystem boundaries, data flow, and invariants. See [PROJECT.md](PROJECT.md) for user-visible behavior and product scope.

## System and browser

`TimelineCore` contains the platform-independent navigator model. `SynologyAPI` separates wire/domain models and the `PhotosTransport` contract from the concrete authenticated HTTP client, and owns credentials, TOTP login, timeline/page requests, thumbnails, original-photo downloads, and ranged video requests. `PhotoCache` owns semantic resource keys, cached-first request coordination, SQLite metadata storage, compressed media files, and eviction. `SynoTimelineApp` is the SwiftUI macOS executable module; its product executable remains `SynoTimeline`.

`CachedPhotosRepository` depends on one `PhotosTransport` contract for login, collection-aware timelines and pages, Personal Space album listing and scanning, favorite and rotation writes, thumbnail regeneration/upload, thumbnails, originals, and video byte ranges. The Synology client rejects initial Favorites requests and all album requests through the timeline endpoint because those collections use different endpoints.

The repository remains the sole coordination actor and caller-facing interface. `RepositoryAuthenticationState` owns login attempts and replayed status; `RepositoryMetadataWork` owns collection epochs, timeline/page jobs, and refresh observers; `RepositoryImageWork` owns shared thumbnail, original, and video-segment jobs; `RepositoryFavoriteState` owns optimistic favorite overrides; and `RepositoryItemMutationState` publishes authoritative/optimistic item replacements. Actor-isolated extensions contain authentication, metadata, media, Favorites, and rotation pipelines. They retain the same suspension points and distinct transfer policies, so mutation ordering, cache-generation checks, subscriber cancellation, and priority promotion remain ordered on the shared actor.

All persisted metadata uses one narrow lifecycle/storage boundary. A `MetadataWorkToken` captures repository admission, whole-cache and metadata generations, shared-job identity, and the relevant collection mutation epoch before network work. Publication and persistence recheck that token; SQLite metadata writes also compare a monotonic row revision atomically, so a page fetch, optimistic Favorites patch, and rollback cannot overwrite a newer same-key value after an actor suspension. Resource-specific algorithms remain in their typed extensions rather than a generic loader. Cache keys are centralized separately from SQLite implementation details. Images retain their independent whole-cache generation and transfer pipelines.

At startup the app reads `USER`, `PW`, and the TOTP secret `OTP` from the ignored `.env`. It opens one shared repository for the app process and starts cached-first Personal Library and Favorites timeline loads concurrently. Personal Library may use `get_init_timeline` on a cold cache before full `get`; Favorites always uses full `get` with `favorite_only=true`. The Personal Space album list is loaded only after the Albums destination is selected, and each album timeline is loaded only after that album has been opened. Album timelines are synthesized from a capture-time-descending item scan because `Browse.Timeline` ignores `album_id`. Identical startup descriptors update verification state without replacing the viewport. Timelines and album metadata are not polled during the run. Successful local favorite mutations trigger a coalesced authoritative Favorites timeline refresh; pages remain demand-driven.

The snapshot preserves every section's date list, offset, and limit, while the navigator deduplicates calendar dates, retains the earliest section index for split days, and sorts newest first. It precomputes year/month boundaries once. Selection is restored by calendar date when a refreshed map arrives. Live changes during a run remain out of scope.

The AppKit photo-viewer canvas draws with a persisted pixel-interpolation preference. Presentation state identifies whether the current bitmap is a provisional thumbnail or the decoded original, allowing the canvas to interpolate always, only while a provisional asset is displayed, or never. Preference changes invalidate the canvas immediately.

`LibraryIndex` hashes the complete, ordered descriptor snapshot and maps each UTC day to exact slices of every contributing section response. Slices carry page-local, day-local, and collection-ordinal coordinates. It also maps ordinals to fixed-grid visual rows and directional destinations across day breaks. `LibraryViewportGeometry` derives exact document height and square-slot positions from descriptor counts and the 3–10 column preference before metadata loads. Retained pages add aspect-fitted image rectangles without moving slots; visible cross-page rows demand every contributing section. Distant slices retain scalar geometry, not item arrays or row views. `LibraryPageWindow` accepts visible and adjacent prefetch sections, retains at most eight pages, emits cached pages promptly, and rejects obsolete responses. The viewport reconciles retained pages after events because buffered hints may be dropped.

Each collection browser hosts an `NSScrollView` in SwiftUI beside the equal-day Canvas navigator. Its flipped document creates pass-through `NSHostingView` rows and date headings only in the visible region and a small overscan, with an AppKit overlay for selection outlines and marquee feedback. It restores scroll position by visible item ID plus pixel offset when possible, otherwise by date and slice position; explicit navigator requests jump to the date's first slice. Scrolling updates the selected date without issuing another jump. Same-day fixed rows remain stable across API slices, page arrival, and eviction; unloaded metadata leaves an exact placeholder slot. AppKit bounds notifications handle scrolling and resize, while thumbnail tasks end as row hosts leave the viewport. Image decoding is limited to two concurrent jobs separately from six thumbnail transfers. The trailing toolbar status observes replaying repository authentication status; failed sign-in remains memoized until explicit retry. Cached data remains usable while signing in or after failure.

Exact section item pages are cached and validated once per run. Timeline and page keys include the collection; thumbnails and originals remain shared. Favorites pages use `favorite_only=true`; album pages use `album_id` plus capture-time ordering. Both remain demand-driven. Items retain server order and are grouped by UTC day, matching section request bounds. `FixedPhotoGrid` supplies pure equal-slot and aspect-fit geometry. Resizing preserves the 3–10 column count; the toolbar and Library menu change it in integer steps. The native viewport creates thumbnail cells for nearby rows. Each cell centers the rendition without cropping, shows cached bytes first, and validates/downloads after current page metadata arrives. A displayed rendition remains visible while it is validated. Six thumbnail transfers and two metadata requests can run concurrently. Pending queues are bounded, with visible demand before prefetch. Shared repository jobs cancel when their last subscriber leaves; cached reads do not wait for login or a network slot. ImageIO downsamples off the main actor; an `NSCache` limits retained decoded images.

Personal Library filtering is a session-derived collection layered over those authoritative pages. After a validated Personal Library timeline arrives, `LibraryFilterController` reads every page key addressable by that snapshot through the repository's network-disabled cached path, with at most two reads active. It retains compact scalar records for sparse source coverage after ordinary page-window eviction; one canonical `(source section, page offset)` sequence, with item-ID deduplication, drives both normalized facet catalogs and filtered registrations. Current-run verified replacements supersede provisional cache records, while late provisional emissions cannot downgrade them. Synthetic days may therefore expand as noncontiguous sections arrive. The browser maps visible synthetic sections back to source sections and sends direction-specific user-scroll demands near either edge. One gesture generation admits at most eight new source sections into an ordered deduplicated queue, and the queue performs at most two cached-first page reads concurrently; passive snapshot rebuilds do not advance it. Empty results use an explicit bounded initial batch because they have no viewport anchor. A `.libraryFilter(UUID)` registration maps each synthetic item to its Personal Library section, page offset, and item ID; repository page resolution rechecks identity and the predicate, retains only eight derived pages, and never persists derived metadata. Metadata reset or a changed Personal Library fingerprint drops the session registration. Favorites continue to patch Personal Library source pages and favorite/rotation broadcasts update visible derived pages.

`TimelineSectionCacheLoader` is the single explicit **Load All Timeline Sections** page scheduler for every persistent timeline collection. It captures one verified collection snapshot, preserves split-day section indices, admits at most two `repository.page` subscribers, and uses collection-scoped page keys and the ordinary repository validation/mutation pipeline. Its collection-neutral event stream carries generic progress plus optional indexed page emissions; display labels stay in the app layer. When Start is pressed, `LibraryModel.discoverTimelineWarmingTargets()` resolves Personal Library and Favorites, loads the Personal Space album list, and starts timeline scans for every album, including albums that have never been opened. `TimelineSectionLoadModel` then applies the same generic loader sequentially to those targets, which keeps page concurrency globally bounded to two and makes another persistent timeline type a target-discovery change rather than a new scheduler. Album work uses the synthesized sections produced by the capture-time album scan; Map/location indexing is excluded. Stored pages are bypassed by default. With **Use Cached Pages**, each section first performs a network-disabled cache probe; any cached page is counted as skipped without validation, and only cache misses proceed to a cache-bypassing network request. Cancellation stops new admission and failure retry retains the original policy. For Personal Library only, the coordinator forwards every cached or verified loader emission through `LibraryFilterModel.ingest`, keeping sparse filter coverage, facets, and active derived results synchronized without duplicating the bulk scheduler inside `LibraryFilterController`.

SQLite holds timeline/page JSON and cache bookkeeping. Compressed image bytes and video segments live in hashed files under an account-scoped directory inside the repository's ignored `.cache/` directory. `CacheLocation` finds the repository containing `Package.swift`, because Finder and LaunchServices do not provide a dependable process working directory. The SQLite index has an explicit schema version; incompatible or unreadable indexes and their media files are recreated from NAS data. The index records validation run, access time, ETag, Last-Modified, content digest, and a monotonic row revision. Settings offers full clear and metadata-only clear. Metadata-only clear advances its storage generation at admission, transactionally removes metadata rows, broadcasts only a successful invalidation revision, and preserves compressed/decoded media data and already admitted transfers. Full clear also advances the whole-cache generation, removes media rows/files, and cancels media work. Disk trimming removes video segments first, then viewer-fetched `xl` previews, full-size images, ordinary thumbnails, pages, and finally unprotected timelines. Preview and ordinary `xl` thumbnails share a key and file; ordinary demand promotes only the entry category, and preview work cannot demote it. The configured budget and media preferences are in Settings. Budget usage currently counts indexed payload bytes; SQLite/WAL overhead and temporary writes are not included in the displayed figure.

The current certificate mismatch is accepted only for the configured Cirrus host. The app's transport-security exception and the URL session trust override are both scoped to that hostname. The URL session uses ephemeral cookie storage, and credentials, OTP values, session IDs, and tokens are never logged. `.env` is a development credential source; a distributable app should move credentials to Keychain.

Unified diagnostics use the stable `local.cirrus.syno-timeline` subsystem with separate viewer asset, original repository/transport, video player/repository/transport, rotation repository/transport, and viewer decoding categories. Video diagnostics record requested/effective quality, metadata/network authorization, cache decisions, byte ranges, response status and timing, AVPlayer state and waiting reason, and sanitized error domain/code. Rotation diagnostics record the item/unit identity, stage, rendition byte counts, response status, Synology error code, revision-poll result, and recovery outcome. Diagnostics exclude filenames, cache keys, credentials, tokens, session IDs, cookies, authenticated URLs, and response bodies. `make debug` opens Console normally and then runs the app in the foreground; the reusable Console subsystem search is `s:local.cirrus.syno-timeline`.

The application shell reuses one virtualized browser for Personal Library, Favorites, opened albums, and session map filters beneath an optional full-window AppKit photo canvas or native video player. A standard `NavigationSplitView` sidebar contains Library plus Favorites, Map, and Albums destinations. Albums opens a full-detail overview grid; opening a card enters the shared browser with a back control and the album name in the toolbar. Map opens a clustered overview; opening a pin or cluster enters the shared browser with a Map back control. The system owns sidebar resizing and toggle placement, and changing destinations closes the viewer. The native unified toolbar overlays detail content. The viewer fits below the toolbar; magnified photos may extend behind it. The toolbar switches from the discrete items-per-row control to media-specific controls, filename, capture-local date, and loading status while viewing. System appearance drives semantic colors in SwiftUI and the hosted AppKit viewport. The app requires macOS 27 and uses native Liquid Glass. Grid column count changes independently of the thumbnail rendition selected in Settings. A compact trailing navigator appears near the pointer, while dragging, or with keyboard focus; its reserved width stays fixed to avoid hover-driven grid reflow.

The app persists one concrete version-3 navigation payload in user defaults: the selected sidebar destination, the last opened album ID, and a dictionary of optional timeline anchors keyed by persistent collection identity. Timeline anchors identify a photo by server item ID and retain an ISO day fallback, layout-relative offset, and server page-offset hint. Restoration first opens the nearest available day, then refines to the photo after its hinted page loads. A restored album ID is cleared only after a verified album list shows that it no longer exists. Session map filters are deliberately not persisted. Corrupt payloads and any schema version other than the current one are discarded completely.

`BrowserScrollIntentCoordinator` owns a single typed restoration, viewport-preservation, viewer-reveal, or selection-navigation intent. New day jumps, selection moves, and viewer requests replace earlier intent; user scrolling cancels pending refinement. Descriptor rebuilds rebase the active intent, while verified page progress survives page eviction until restoration settles. Saved anchors preserve their pixel offset; viewer reveals center the photo and bind deferred rectangle completion to the request identity. The AppKit adapter applies scroll effects and retains responsibility for bounded page demand and row hosting.

## Full-size image resources and navigation

`PhotoViewerSession` navigates an immutable `LibraryIndex` using section-prefix counts and exact page offsets, including thumbnails carried into rows across API page boundaries. It retains at most three metadata pages and the current plus two adjacent encoded originals. Replaying snapshots carry a selection generation; request tokens and generation checks reject obsolete results during rapid navigation. Verified metadata preserves the selected item by ID if its page position changes. Provisional metadata may read cached images but cannot authorize image downloads. The session privately observes successful metadata invalidations, releases discarded metadata/navigation work, and exposes an ordinary reopen state while the presentation keeps its already decoded image until the shell closes the obsolete context.

The session remains the sole actor for viewer coordination. Its `ViewerMetadataWindow` value owns ordinal lookup and bounded page/job retention; `ViewerImageWork` owns encoded bytes, image tasks, and shared cancellation/reset operations. Selection changes clear displayed bytes, retries preserve them, and closing cancels all viewer image work. Actor-isolated extensions separate metadata reconciliation, current asset loading, adjacent prefetch, and Favorites mutations without introducing additional actor hops.

The original-photo repository uses separately keyed compressed files and conditional validation once per run. Two transfer slots allow at most one speculative request, leaving capacity for visible demand. Selecting an in-flight neighbor promotes its shared job instead of downloading it again. Leaving an image cancels obsolete work; neighboring images are requested only after the current image succeeds. Cached bytes remain usable if validation fails.

When “Load large previews in viewer” is enabled and the configured library rendition is smaller than `xl`, the viewer displays and fetches the configured thumbnail immediately, while cached `xl` previews and originals are also read immediately. Network-backed `xl` and original requests wait for the selection to remain stable for 100 ms, then start concurrently and warm one adjacent `xl` thumbnail in each direction. This avoids expensive transfers for intermediate selections during key repeat. These requests use the shared thumbnail pipeline but write the lowest-retention preview category. The viewer accepts an `xl` upgrade and retains it if original transfer or decoding fails; a successfully decoded original remains final. Adjacent previews retain compressed bytes only and obsolete work is cancelled. If the configured rendition is already `xl`, its cached data is still read immediately and its network request uses the same stability delay; the separate preview category is inactive and ordinary thumbnail demand transparently promotes any matching preview entry without copying or downloading it again.

Thumbnail activation supplies the displayed image and an AppKit window-coordinate source rectangle for the expansion transition. The viewer keeps its image and zoom state per window; arrows change the desired selection and issue bounded background reveal requests to the browser. Back/Escape resolves the current item's live cell rectangle and collapses into it, with a timed fade fallback when no live destination exists. A changed authoritative timeline snapshot invalidates ordinary navigation with an explicit reopen message, while local Favorites refreshes leave the open session playlist intact. Preview and original upgrades share the current transform.

The executable separates viewer source anchors, window chrome measurement, presentation and decoding, SwiftUI overlays, the canvas bridge, and AppKit canvas input and animation into individual files. The canvas fills the split view's detail width and reserves the measured toolbar height when fitting an image.

Personal Space item pages include optional `additional.favorite`; omission means the item is not favorited. The viewer requires verified item metadata before enabling its heart toolbar button or the Library menu's `.` command. `SYNO.Foto.Browse.Item.set_favorite` writes are serialized by the shared repository and remain active if the viewer closes. The viewer tracks pending writes and errors by item ID, so navigating away does not disable the heart for another photo. Before awaiting the NAS, the repository broadcasts the new status and patches cached metadata in the source collection (or the corresponding Personal Library pages for a Favorites action). It does not fabricate Favorites membership or page order. Successful writes schedule a coalesced authoritative Favorites timeline refresh; a mutation epoch rejects older Favorites page and timeline work. Write failure restores the prior status and patched cache entries, while refresh failure keeps the successful status and reports stale Favorites metadata. An open Favorites viewer separately records locally changed members' original day offsets, metadata, optimistic heart value, and last confirmed server membership. Translated, cache-bypassing page reads use confirmed membership for offsets while a write is pending, then cancel and replan after commit; they merge changed members back into evicted pages to preserve the opening playlist with at most three resident pages until close. The timeline shows a heart badge for favorites.

The browser reuses the same favorite pipeline for selections. The Library menu's `.` command and a persistent toolbar heart route to the active viewer or to the active browser selection. `SelectionFavoriteResolver` maps selected ordinals to `LibraryIndex` locations, reads only the sections that contain them (at most two pages concurrently, waiting for verified metadata), and aborts if the index fingerprint or a previously known item identity changed. A mixed selection favorites only its unfavorited items; an all-favorite selection unfavorites them all, and the affected count (not the selection count) drives a window-modal confirmation above five items. `SelectionFavoriteAction` carries the resolved IDs, one target value, source sections, and item metadata. `setFavoritesBatch` atomically claims every ID against the pending set, publishes one batched change, patches each affected cached page once, then writes fixed-size chunks in order; on a chunk failure it keeps completed chunks, rolls back only the failed and unsubmitted IDs, and schedules one coalesced authoritative Favorites refresh. The single-item viewer path remains a wrapper over the same batch entry point.

`SelectionRotationResolver` uses the same bounded verified-page pattern for still-image rotation and omits unsupported videos. Normal rotation publishes an optimistic quarter-turn item replacement, patches affected page caches, sends `Browse.Item.set`, then replaces the projection with an authoritative ID lookup; failure restores the prior items and cached metadata. The viewer also rotates its currently displayed bitmap immediately. ImageIO applies the unchanged original file's EXIF orientation during full-image decoding; the viewer then applies only the quarter-turn delta from `orientation_original` to Synology's current `orientation`. Server-generated thumbnail bytes receive no second orientation transform. The native Edit menu owns icon-labeled left/right commands for normal and thumbnail-only rotation plus automatic thumbnail repair; only normal rotation is also exposed in the toolbar. Thumbnail-only rotation is a separate cancellable repository stream: one item at a time downloads all three ready renditions, rotates JPEG bytes locally, calls `set_regenerating`, uploads the multipart converted files, polls a bounded number of times for the new cache key, and publishes the refreshed item. Automatic repair first obtains the original through the shared full-image cache and uses a separate ImageIO analyzer actor to create bounded, orientation-normalized luminance rasters. It evaluates four relative quarter turns per rendition using normalized luminance and edge correlation with aspect, absolute-score, and runner-up-margin gates. `sm`, `m`, and `xl` must each be confident and unanimously select the same turn before `set_regenerating`; a unanimous zero-turn result performs no write, and missing, undecodable, ambiguous, or disagreeing input fails before server mutation. Every ambiguous regeneration/upload failure or cancellation performs detached `restore_from_regenerating` cleanup and a cancellation-independent bounded authoritative reread, adopting any advanced cache key before reporting failure. The transport exposes byte progress for original downloads and multipart uploads; request timeouts are inactivity limits while the resource timeout is a generous absolute cap. Full originals use an explicit `URLSessionDataDelegate` that accumulates the body and publishes every delivered data chunk instead of relying on a buffered convenience download. The modal maps each current photo's downloads to 0–1/2, local analysis/encoding to 1/2–2/3, and upload to 2/3–1. The download aggregate estimates `sm` at 60 KB, `m` at 150 KB, and `xl` at 1 MB, adds the original's metadata filesize (or a 5 MB fallback), and replaces the original estimate with HTTP expected bytes once available. The status names the active rendition, live original bytes update the fraction, and SwiftUI animates between callbacks. A bounded-height scroll view shows only the final outcome for each photo.

The app hosts a floating Info utility window toggled by the Library menu's Cmd+I command or the toolbar info button beside the favorite control. `InfoPanelModel` publishes a synchronous count and day-range summary for a multi-item browser selection, then runs a 150 ms-debounced `SelectionInfoResolver` for the exact cumulative size and photo/video counts; the resolver reads only timeline sections containing selected ordinals, at most two concurrently, cancels superseded generations, and leaves the size unavailable when a section fails or any selected item lacks a filesize. The panel always shows the viewer's current item while the viewer is open, shows a placeholder when nothing is selected, and performs no page reads while hidden. Item pages bundle `exif` and the slash-prefixed Personal Space `folder` path with the existing `additional` fields, so single-item camera details and a copyable path are available from the same cached payload; the page cache key derives from the shared request-field list. Single-item filename and item ID are also individually copyable, while identity details are omitted for multiple selections. The utility window is transient, ignores the window cycle, and keeps only its close button enabled; closing the main window dismisses it.

Synology's `PhotoItem.time` is a capture-local wall clock encoded as epoch-shaped seconds, not an absolute instant. Timeline grouping and UI formatting both use GMT calendar components so a photo taken at 21:00 displays 21:00 regardless of the Mac's current timezone. No timezone is inferred from location or device state. Favorites is treated as a filter over the same stable chronological item order: removing and re-adding membership does not redefine an item's ordering key.

`FullImageDecoder` performs orientation-aware ImageIO decoding away from the main actor. It preserves original pixel dimensions, admits one decode and one replaceable waiting request, and rejects images above a 384 MB decoded-image limit with an explicit error. Neighbor prefetch retains compressed data only. `PhotoViewportTransform` computes fit, pointer-anchored magnification, and bounded pan in canvas coordinates, independently of the interface.

## Video playback

Item pages decode the observed `video_convert` array and its `mobile`, `low`, `medium`, `high`, and `orig_h264` quality identifiers. `VideoQualityPreference` is a semantic user preference rather than a wire value. Automatic targets High. Resolution considers only known qualities advertised by the current item, minimizes ladder distance, and orders an equal-distance lower rendition before a higher one. Original is a separate stored-file variant; it is also the fallback when no converted rendition is advertised. Resource keys include account namespace, thumbnail cache revision, effective variant, and segment index.

`SynologyClient.videoRange` uses authenticated `SYNO.Foto.Streaming` v2 requests for converted variants and `SYNO.Foto.Download` v2 for stored originals. Both paths require a valid `206` response, matching `Content-Range`, media content type, and exact payload size. The repository aligns demand into 64 KiB segments, coalesces identical segment jobs, limits video to a separate two-transfer lane, and assembles only the caller's requested bytes. The deliberately small segment is the atomic buffered `URLSession.data(for:)` response: it lets a slow NAS/link return incremental ranges to AVFoundation before its resource-loader stall window expires. Video segments share the main disk budget, rank below every photo rendition for eviction, survive metadata-only clear, and are removed by full clear. There is no adjacent-video prefetch. Current item metadata must be verified before the player may start a new network range; cached ranges remain readable without network authorization.

`VideoPlayerView` wraps `AVPlayerView` and gives `AVURLAsset` an opaque custom-scheme URL. `VideoAssetLoader` translates AVFoundation content-information and byte-range loading requests into repository calls without exposing credentials or authenticated NAS URLs. The existing thumbnail remains behind the player until playback starts. Replacing or dismantling the view pauses the player, cancels loader tasks, and releases the asset; its identity includes the viewer selection generation and effective rendition so stale work cannot be reused for another item. Native controls own seeking and play/pause, while the viewer keeps its existing menu-backed close and previous/next navigation behavior.

## Locations and map

`Browse.Item.list` pages can carry an optional `additional.gps` object. `PhotosRequestFields.pageAdditional` includes `gps`, so every page (normal, album, and filtered) exposes `PhotoItem.coordinate` and the info panel can show location context without a separate request. Items without a location omit the key.

The Map destination is backed by one persisted location index. `CachedPhotosRepository.locationIndex()` emits cached records first and keeps them visible as explicitly unverified if validation fails. It then joins the ordinary Personal Library timeline pipeline and waits for that timeline to be validated in the current run before comparing fingerprints. A match finishes without a location scan; otherwise one shared background scan fetches `Browse.Item` pages (`limit=1000`, `additional=["gps","thumbnail"]`, at most two pages in flight at prefetch priority, each acquiring the metadata gate individually) and persists the located records with the validated fingerprint captured at scan start. Reaching the scan's safety cap on a full page fails instead of persisting a partial index. `total` comes from the timeline section limits so progress is exact. The scan keeps running after its last subscriber leaves so the next open is fast, and metadata reset cancels it through the shared lifecycle. The payload uses the `locationIndex` cache kind and a high-retention class that survives normal trimming, directly below the active timeline.

Strict bounded Diff v1 transport, cursor/change models, arbitrary-ID location lookup, and a pure conservative location-delta merge are implemented but have no production freshness authority. The mandatory large-interval completeness, cursor reset/rejection, feed visibility delay, positional-scan completeness/stable equal-time ordering, and Personal Space access-change evidence is not available. Until those gates pass, Map deliberately retains the fingerprint path above and never mints or persists cross-run Diff proof.

`MapClusterBuilder` (`TimelineCore`) is a pure, deterministic, grid-accelerated radius clusterer: it visits records newest-first and joins each to the nearest open cluster whose newest member is within one radius on both axes, otherwise opening a new cluster. Two nearby photos therefore never split just because a grid boundary falls between them, and clusters never chain arbitrarily far. The radius starts at the finest useful value (viewport span / 512, raised to the viewport's on-screen pin pitch) and doubles until the cluster count fits ~256 annotations, so low zoom shows counted clusters, medium zoom splits them, and a lone photo renders a single thumbnail pin. Records sharing an identical coordinate stay clustered at every zoom; the antimeridian is not handled. `MapBrowserModel` derives the radius from the current camera region and view size, reclusters off the main actor with a ~120 ms debounce after camera changes or window resizes, fits the camera once to the records' bounding region, and keeps an ID-to-index map so opening a pin or cluster resolves its member records in O(members).

Opening a pin or cluster passes only selected IDs and an opaque location revision to the repository. The repository atomically verifies membership against its current location records, constructs a session-only `.mapFilter(UUID)` collection with a synthetic day-grouped `TimelineSnapshot` (250-ID sections), and owns the exact IDs and dependency revision behind every section. The existing virtualized browser, selection, viewer, info panel, and Favorites machinery run unchanged because filtered pages go through the same `page(_:collection:)` entry point. A bounded first pass reads every covering Personal Library page cache-only and emits the available filtered items before any network-backed stream can suspend; an optional second pass validates the ordinary pages and publishes a verified replacement only when every requested ID is present. A small session page cache short-circuits repeated complete requests. Because the underlying fetch is the ordinary timeline page request, cached-first delivery, once-per-run validation, request sharing, and priority promotion all apply unchanged, and pages fetched for a filter remain useful to the timeline. A semantic location-index replacement publishes a typed collection invalidation, removes dependent filter pages, closes an obsolete filter/viewer through the shell, and returns to the preserved Map camera. Favorites writes on a filter selection patch cached Personal Library pages by item day, and the filter's session pages pick up override changes through the existing broadcast stream. The filter descriptor, camera, and pages live only for the app run and are never persisted for restoration.

The info panel appends a small `Map(initialPosition:)` below the metrics for a single located item or below the size row for a multi-selection, with one `Marker` per located photo (rendered pins are capped at 500 while the count text stays exact). The map is omitted entirely when none of the involved photos has a location.

## Geometry and input

Each populated day owns the same fraction of the usable track. Empty days occupy no space. Item counts do not influence spacing.

For `N` dates, track origin `top`, track height `H`, and pointer `y`:

```text
fraction = clamp((y - top) / H, 0, 1)
dayIndex = min(N - 1, floor(fraction * N))
markerY = top + H * (dayIndex + 0.5) / N
```

This gives constant-time pointer lookup. A single `Canvas` paints the track, month marks, year labels, and selection indicator. One transparent rectangular view handles continuous hover and click/drag input. There are no per-day views or hit targets. Year labels are culled when less than 25 points apart, without changing the underlying date geometry.

More populated days than screen pixels necessarily means some days cannot be individually targeted with the pointer. Arrow keys and the accessibility adjustable action allow exact single-day stepping. Hover feedback includes both year/month and the exact selected calendar day.

## Selection contract

`TimelineNavigator` exposes a selected day index through a binding. In Personal Library, user input creates a jump request with a fresh identity, including a repeated selection of the same date. Browser scroll feedback updates the bound selection without creating a jump. Date selection survives a changed index by using the nearest remaining older day. A section can contain several days, so the browser resolves the exact day slice before scrolling.

Each browser collection keeps a session-local `LibrarySelection` as normalized ordinal ranges. Pointer clicks replace or add one item; Shift-Option-click adds the inclusive range from the nearest already-selected ordinal, with the earlier ordinal winning an equal-distance tie. Marquee selection replaces from current hits, while Shift-marquee applies symmetric difference against the gesture-start baseline. Cmd+A selects the collection's full ordinal range without materializing item metadata. Directional commands choose the earliest border for Left/Up and latest border for Right/Down. Shift commands retain the gesture-start selection, a fixed border, and a movable cursor; the active inclusive reading-order range grows or shrinks as the cursor moves without removing baseline items. Page verification compares ordered item-ID signatures and invalidates ordinal selection if membership or order changed. Selection survives row recycling, scrolling, sizing changes, and destination switching without materializing metadata for every selected ordinal. The key window's AppKit browser responder dispatches the same commands defined in the Library menu; sidebar, navigator, viewer, Settings, and other-window focus do not invoke browser selection. Selection mutations continue to resolve verified metadata before presenting or executing an action; actions on the entire collection always require confirmation, while other favorite changes retain the affected-count threshold.

Location labels remain deferred.

## Cache direction

`ThumbnailRangeDownloader` handles explicit range downloads from the Library menu. The nonmodal picker maps its two handles to oldest-to-newest populated dates and sums the selected distinct-day item counts. It uses a validated snapshot, resolves every contributing section (including split days), and filters each page to the selected day slices. One metadata page and two low-priority thumbnail workers are processed at a time; no whole-library photo array or decoded images are retained. It shares the repository's jobs and cache with browsing. Progress distinguishes fetched, reused, unavailable renditions and errors; successful processing does not pin entries or override the cache budget. Closing the download window cancels its work.

Typed finite `AsyncStream` results emit cached values first and current values after validation, then finish. Thumbnail GETs use `If-None-Match` or `If-Modified-Since` when cached validators exist, and accept 304 only with local bytes. The NAS remains authoritative; cached metadata is provisional until validated. See [cache plan](plans/WIP_CACHING_PLAN.md) for evidence, current limitations, and future work.

The cache-location rationale and requirements for any future return to macOS's purgeable Caches directory are recorded in [decision 001](decisions/001-development-cache-location.md).
