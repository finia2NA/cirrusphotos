# Personal Space folder browsing plan

Implementation tracked in [#14](https://github.com/finia2NA/syno/issues/14). This is a proposal, not a description of current behavior. Album folders are separate ([#54](https://github.com/finia2NA/syno/issues/54)).

## Scope and capture evidence

Add a Library toolbar control to switch between the existing timeline and a navigable Personal Space folder view. At each level show immediate child folders as album-like cover/name cards and the current folder's direct photos and videos using the shared browser. Both must remain accessible when a folder contains both. Show the final path component as the card name; retain the server ID and parent/path for navigation. Empty folders and missing covers need a normal placeholder. Back navigates to the parent and switching to timeline returns to the existing Library. Do not add filesystem mutations, Shared Space, album-folder browsing, or recursive inclusion of descendant photos.

`docs/captures/folderview.har` records `SYNO.Foto.Browse.Folder` v2 `get` with `id=0` resolving the Personal Space root and `list` with parent `id`, offset/limit, filename ascending and thumbnail additional data. Folder names are slash-prefixed paths, `parent` is an ID, and `additional.thumbnail` is an array that may be empty or contain multiple item thumbnail descriptors. The captured root points to itself as parent. `SYNO.Foto.Browse.Item` v7 `count` and `list` use `folder_id`; the captured populated leaf has 48 items. Folder listings omit a total. Do not put raw HAR contents, credentials, paths, or sharing tokens in tests, logs, or issues.

On 2026-11-01, a disposable phototest filesystem fixture established the following for this NAS: root self-parenting; a mixed folder with eight direct photos, three populated children and one empty child; all four children listed with the correct parent; and item count/list returned only the eight direct photos. Item pages of two and folder pages of one matched the full ordered lists without duplicates, and exact-multiple pagination ended with an empty page; repeated reads matched. Six items shared one timestamp and two another; exact-second and UTC-day `start_time`/`end_time` reads matched the unbounded results, with descending `takentime` order. A ready folder thumbnail descriptor returned a nonempty image response through the existing thumbnail URL. The fixture was removed and the original environment and cache restored. These are small, quiet, single-run observations, not proof of behavior at production page sizes, local-day boundary edge cases, or during concurrent NAS changes. No raw responses were retained.

## 1. Validate the read contract

- The focused probe above provides a basis for implementation. Add regression coverage for those observations and use bounded read-only follow-up probes if production-sized pages, local-day boundaries or an observed ordering failure require it. Compare IDs across pages and never infer completeness solely from an HTTP 200 or a count when pagination is inconsistent.
- Prefer focused sanitized response fixtures and existing mock transport tests. If the actual server does not support stable date-scoped reads, implement a bounded, ID-based detail materialization path through the repository using the enumerated membership, rather than using unfiltered library results or building a parallel UI-owned engine. If neither approach can preserve membership and paging integrity, stop and report the specific missing evidence; ask for a HAR capturing that interaction when useful. A HAR showing a mixed folder and pagination would be useful if read-only probing cannot settle these questions.

## 2. Repository and server integration

- Add folder summary/envelope models in `Sources/SynologyAPI/FolderModels.swift` and read-only `get`/paged `list` methods to `SynologyClient.swift`, mirroring album transport and validation. Decode optional/empty thumbnail arrays and retain usable thumbnail descriptors; treat root self-parent specially and reject malformed IDs or incomplete pagination. Terminate listing on a short page, including an extra request for an exact multiple, with explicit bounds and duplicate checks. Failed or partial reads must never replace a complete cached listing.
- Add `.folder(Int64)` plus stable `folder:<id>` serialization and a `folderID` accessor to `PhotoCollectionDescriptor` in `PhotoModels.swift`. Update exhaustive switches, `CollectionMetadataSource`, collection ordering in `CollectionDayCatalog.swift`, `CachedPhotosRepository+Metadata.swift` and other album-only assumptions. Folder membership is persistent and authoritatively validated per run; session filters remain derived and folders are loaded on demand.
- In `SynologyClient.swift`, supply `folder_id` for scoped reads. Generalize the bounded album item enumeration in `CachedPhotosRepository+MetadataAcquisition.swift` and `readAlbumCatalogBatch` to share the same catalog/membership construction for folders, retaining IDs and timestamps, detecting duplicates, honoring request limits, and using the same explicit ordering for subsequent reads. Do not accidentally call the unscoped Timeline endpoint for folders. Rename album-specific membership types where they now represent multiple sources. Keep canonical item details, selection resolution, filters and viewer access in the existing metadata engine.
- Add repository-owned, account/host-namespaced cached-first root and immediate-child list resources, e.g. `CachedPhotosRepository+Folders.swift`, with request coalescing, admission/reset fences, per-run validation and stale-on-error behavior analogous to `CachedPhotosRepository+Albums.swift`. Persist only complete child snapshots, including a verified empty list, in `MetadataStore.swift`; distinguish absent from empty and retain a cached snapshot when refresh fails. Include cache reset and schema-version discard handling. Reuse the shared thumbnail cache via `thumbnailWithFallback`, choosing a usable descriptor and falling back to a placeholder; do not create a separate media cache.

## 3. Navigation and presentation

- Extend `AppShellView.swift`, `LibraryModel.swift`, and `NavigationRestoration.swift` with Library timeline/folder mode and a folder path or parent stack, scoped to the active repository namespace. Resolve root through the server rather than assuming its ID. Restore only validated hierarchy where possible; retain cached navigation offline, and clear a missing path only after an authoritative complete parent list proves it absent. Bump and discard the incompatible navigation format according to project policy. Preserve collection-specific scroll anchors with the folder descriptor.
- Add a folder overview/level view alongside `AlbumsOverviewView.swift`, extracting shared card/cover presentation only where useful. Place child cards above the current folder's direct item browser with a clear way to access both even for a large list; retain virtualized photo browsing and avoid an unbounded nested scrolling layout. Integrate Back/Escape with existing navigation, and make the toolbar mode control available in Library. If adding any keyboard shortcut, define it in the macOS menu bar as required by `AGENTS.md`.
- Reuse `LibraryBrowserView`, viewer, selection, favorites, rotation, downloads, and metadata filters with the folder as source. Verify album-only commands and headers do not appear merely because a folder is a persistent collection. Selection operations must resolve only the current folder membership. Represent loading, genuinely empty and stale/error states distinctly without hiding cached content.

## 4. Verification and completion

- Add targeted `SynologyAPITests` for sanitized folder models, request parameters and pagination edge cases; `PhotoCacheTests` for scoped membership, ordering/page boundaries, partial refresh, empty lists, offline cached reads, reset fencing and filters; and `NavigationRestorationTests` for hierarchy, parent/back and missing-versus-unverified behavior. Cover mixed direct items and child folders in an appropriate model test. Existing tests remain valid; run relevant suites and the full suite when integration is complete.
- Perform bounded read-only acceptance checks with the disposable account; no write endpoint exploration without user confirmation. Check nested, empty, mixed and large folders, viewer and mutations already supported for items, mode switching, relaunch, and offline/failed validation. Do not use computer control unless the user explicitly requests it. Document confirmed behavior in `docs/PROJECT.md` and `docs/ARCHITECTURE.md`, and update the root overview in `AGENTS.md` once implemented.

## Known risks

The small fixture does not prove stable folder paging during concurrent NAS changes, at production page sizes, or across every time-zone boundary. Treat inconsistent coverage conservatively and retain the last verified cache. Full folder catalog enumeration has the same large-collection cost as albums; keep requests bounded and surface loading rather than claiming immediate verification. The exact combined folder/card and virtualized-browser layout requires care; avoid making child folders inaccessible or nesting competing full-height scroll views.
