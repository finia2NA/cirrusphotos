# Product

This document is the source of truth for current product behavior and scope. See [ARCHITECTURE.md](ARCHITECTURE.md) for implementation structure and invariants. It describes what users see and can do, not how it is built.

## Purpose and constraints

Cirrus Photos is a macOS 27+ SwiftUI client for browsing a very large Synology Photos library hosted on the NAS `cirrus`. Responsiveness with previously cached data matters more than minimizing request count. The application is an alpha: incompatible preferences and caches are discarded instead of migrated before 1.0.

The Synology Photos service is authoritative. The client does not poll for external changes during a session. Demanded resources are normally validated once per run (thumbnails excepted: a changed thumbnail always gets a new server cache key, so cached thumbnails are not revalidated), while cached content remains usable when the network is slow, unavailable, or validation fails. Pages that the run's change feeds show as unchanged count as validated without being read again.

Sign-in uses the credentials described in the README (`.env`); if the NAS requires a one-time code, login reports an error asking for `OTP`.

## Navigation and collections

The native split-view sidebar contains Library, Favorites, Recently Added, People, Subjects, Tags, Map, and Albums destinations, followed by pinned albums. The app restores the last persistent destination and collection-specific photo/date scroll anchors. Session Map filters are not restored.

The toolbar space selector switches between Personal Space and Shared Space independently of albums. Shared Space provides cached-first Library, Favorites, People, Subjects, Tags, folders and Map with thumbnails, selection, Info and metadata filters, plus the common viewer, original stills, ranged video, photo downloads, favorites, photo rotation, thumbnail rotation, ratings, tags and deletion. Shared Space Recently Added and external-editor handoff are unavailable (Recently Added has no established Shared Space endpoint), and Shared Space photos can be added to owned albums (see Albums). Converted video and Live Photo motion use inferred Shared Space counterparts with validated responses; failed converted playback falls back to the original video, and unavailable motion stops safely.

**Library and Favorites** show the whole collection in one day-grouped grid. **Folders**: the Library toolbar switches between the timeline and folders in the selected space. Folder mode shows immediate child folders as cover-and-name cards (a folder shows up to four covers: its own, then its subfolders', then its cached photos), with direct photos and videos below in the same scrolling browser, and a leftmost Back button returns to the parent. A folder with child folders but no direct photos leaves the photo area blank; an empty leaf says so. Folder mode and path are restored independently per space and are scoped to the account and server. Only direct photos are included, not descendants.

**People** lists visible recognized people with face covers and item counts. Opening a person reuses the shared browser, viewer, selection and metadata filters. A person card's Rename command changes the name; as a name is typed, matching named people in the same space appear with face thumbnails, and choosing one makes it a merge target. Merging asks for confirmation and the target identity is retained. The result is confirmed by refreshing the server index, and an uncertain outcome is reported for review before retrying.

**Subjects** lists Synology's recognized categories with cover and count; opening one shows its photos in the shared browser. Subject management is not implemented.

**Tags** lists Synology tags with cover and count; opening one shows its photos. Tags are assigned and removed from photos (see Actions); to find photos by tag within a library, favorites, folder or album, use the Tags and Rating criteria of the filter instead of opening the tag.

**Recently Added** shows the NAS collection grouped by indexing day and ordered by the server. Capture dates remain available in photo metadata. Membership is determined by the NAS, not by a client-side age threshold.

People, Subjects, Tags, folders and Recently Added are cached-first and remain available when validation fails. Back or Escape returns from an opened person, subject, tag, album or map result.

## Browsing and selection

- Collections share a virtualized, day-grouped fixed grid with 3–10 square slots per row, a small leading content inset, and a persisted preference for aspect-fitted or square-cropped thumbnails. The thumbnail-size slider and Cmd +/- also set the cards per row in the Albums overview and the People, Subjects, Tags and folder grids. A toolbar button beside the size control and the Library menu's **Crop Thumbnails to Square** command toggle the crop preference; toggling animates only the visible thumbnail frame within each fixed slot, and with Reduce Motion the change applies immediately.
- The compact day navigator gives equal space to each populated day and appears near the pointer or with keyboard focus. A persisted option can instead keep its rail and current selection visible while idle.
- Click, Shift-click, Shift-Option-click range selection, marquee, Shift-marquee, Cmd+A, and menu-backed arrow commands select across day and page boundaries.
- Edit > Copy (Cmd+C) on a browser selection copies one `filename,id` line per item, with no header row (CSV-quoted where needed). Unloaded selected items are resolved first. The same text is offered beside the file when dragging out of the browser or the viewer, so text fields accept it while Finder and Photos take the files; it is offered only when every selected photo is already loaded, and albums do not offer it. Pasting files into Finder or Photos is not supported; use drag and drop.
- A session-only metadata filter is available for Personal and Shared Library, Favorites, opened folders and albums, incoming albums, and Map pin or cluster results. Criteria: filename, media kind, camera, lens, literal file extension, tags (any selected), star rating (any, unrated, or at least one to five stars), megapixels, size, ISO, focal length, aperture and shutter speed. Everything uses cached metadata, so no server request is made and filtering works offline. Filename search is a case- and diacritic-insensitive substring; the `.*` button switches to a case-insensitive regular expression matched anywhere in the filename. Matches from already cached pages appear immediately, and results expand as the background sync and browsing cache more pages; scrolling near the edge of the results requests nearby source sections first. Failed sections can be retried explicitly. Camera, lens and extension options are cached per collection and shown while discovery runs. Filters are cleared when the source collection changes and are not restored after relaunch. Map filtering applies only within the selected pin or cluster.

## Actions on photos

- **Favorites** appear as heart badges. The toolbar and Library menu `.` command toggle the active viewer photo or browser selection, with confirmation when more than five items are affected or the entire collection is selected. Favorite writes are optimistic and serialized; a failure removes the pending state. A Favorites viewer keeps its opening playlist while membership changes.
- **Delete…** (Command-Delete in the Library menu, and the browser context menu) permanently deletes selected photos and videos from Personal Space, Shared Space, or an owned album's verified members. A confirmation sheet warns first; confirming closes it and the deletion runs in the Activity panel. Afterwards the app reads the items back, reports any that remain, and reloads all collections. Deleting from an album deletes the item everywhere, unlike **Remove from Album…**. Deletion from the viewer, mixed Personal/Shared selections and incoming albums are unavailable.
- **Rating and tags.** The browser context menu, the viewer context menu and the Library menu set a rating of zero to five stars (digit keys 0–5 in the Library menu), **Add Tag** (an existing tag, or **New Tag…**) and **Remove Tag**, on the viewer photo or browser selection in Personal Space, Shared Space and owned albums. Tags are listed from the item's own space, so albums offer only **New Tag…**. Edits are not optimistic: the app writes, reads the photos back, and updates the cached rating and tags and the open browser and viewer. Incoming albums and mixed-space selections are unavailable. Tags are not renamed or deleted; a tag disappears when its last photo loses it.
- **Rotation.** Toolbar controls rotate the active viewer photo or the current browser selection left or right. Rotation is optimistic, supports photos and Live Photo stills, skips videos, and adopts refreshed orientation, resolution and thumbnail descriptors from the NAS. The Edit menu also has icon-labeled commands for thumbnail-only rotation and **Fix Thumbnail Rotations…**. Thumbnail-only rotation runs in a modal, cancellable progress workflow that replaces only the server's small, medium and large thumbnails and leaves the original and its orientation metadata unchanged; a log lists one outcome per photo (applied rotation, already correct, or failure reason). Automatic repair compares the full image with each thumbnail and changes a photo only when all three thumbnails independently make the same confident choice; ambiguous, undecodable or missing renditions are left alone. A failed or cancelled repair restores the affected thumbnails. Shared Space uses inferred counterparts for thumbnail regeneration that have not been verified on a disposable fixture.
- **Downloads.** Right-clicking a photo in any browser or the viewer offers original and compressed JPEG downloads, to the configured folder (default: the macOS Downloads folder) or a folder chosen for that download. Right-clicking a selected photo downloads the selected still photos; right-clicking another photo selects it. Videos are skipped. A single ordinary photo's original can reuse cached full-resolution bytes; compressed JPEG, Live Photo and multi-item downloads use the server response, a ZIP that is unzipped and saved as a folder of files named after the archive, numbered if it exists. Files are staged and only completed files are placed in the destination; existing files are never overwritten.
- **Edit With** (same menus) works on the photo under the pointer even when several are selected. macOS lists applications registered for the file type, with an **Other…** chooser. The app creates a separate original copy in `Documents/SynoTimeline Edits`, keeps existing copies, and opens the copy in the chosen application. Editor changes stay local and are not uploaded. RAW files indexed as Photos items use the same path; separate unindexed RAW or sidecar files are not discovered.
- **Drag out.** Dragging a photo from a browser or the viewer to a file-promise destination copies the original on drop; a Live Photo provides its still. Dragging several photos produces one folder of unzipped originals. The preview uses at most 20 loaded thumbnails with a count badge and follows the thumbnail shape setting. Videos are skipped. Downloading starts after the destination accepts; progress and failures appear in the Activity panel. At viewer fit zoom dragging the image starts an external drag; at higher zoom it pans. Marquee selection starts on empty browser space.
- **Upload.** Drag local image files from Finder onto a Personal or Shared Space library timeline, the folder shown in Personal folder view, or an owned album's browser, card or sidebar pin. Folder drops go into that exact folder with no date subfolders. Local files are preserved and the NAS's ignore-duplicate behavior applies (an existing item can still be added to an album). Each drop is one Activity entry with progress, cancellation, per-file errors and retry. A successful or uncertain upload refreshes the affected library and album; check the destination before retrying an uncertain transfer. Thumbnails of uploaded items can appear up to about a minute later while the NAS generates them. Incoming albums, videos and watched-folder uploads are unsupported, and Shared Space folder uploads are unverified.

## Albums and sharing

On the NAS, sharing an owned normal album adds access settings to that same album, which stays in the normal album list. A shared album is distinct from Synology's Shared Space. Albums retain their own authority and ignore the selected space.

- **Overview.** Albums shows Albums, Shared Albums, and Shared with me in that order, each limited to one responsive row with independently persisted expansion; a persisted sort orders each section by name (default), newest or oldest creation time. The toolbar's plus button creates an empty album. Cards show cover, name and item count. Owned cards offer the four photo download commands for the complete album without opening it; videos are skipped and an empty or video-only album reports no eligible photos.
- **Opened album.** Reuses the shared browser with a scrolling header of cover, name, capture-date range, sharing status and recipient avatars (with hover names), also while loading or when empty or filtered. Escape or Back returns to the overview.
- **Members.** Owned albums can hold Personal and Shared Space members together, including contextual thumbnails, details and original stills. Item actions and downloads need fresh matching reads that establish one source space for the whole selection; ambiguous or mixed-space operations report an error. Album video and Shared Space album contribution are unavailable. Live Photo motion works in owned albums once the member's space is verified on demand; an ambiguous origin stops motion safely.
- **Adding and removing.** The Library menu offers **New Album…** and **Add to Album…** for the browser selection; photo and video context menus offer **Add to Album** (including **New Album…** and eligible sidebar pins first) and, in normal albums, **Remove from Album…**, which removes membership without deleting library items. The chooser lists albums the server reports as addable. Operations capture and verify their selection before writing. The sheet closes on submit, menu and drag additions open no sheet, and album writes run one after another in the Activity panel. Shared Space selections use the same commands; contributing them to Shared with me albums is unavailable.
- **Dragging.** Drag a Personal or Shared Space browser selection onto an owned album card or pinned row to add its photos and videos (existing members are skipped), or, for Personal selections only, onto a Shared with me album when the recipient has Provider access. Hover over Albums in the sidebar to open the overview during a drag. Drag an owned album card or pin to a file-promise destination to export its eligible originals as an album-named folder. Drag a card to the sidebar to pin it, or a pin to reorder. Internal drops do not start downloads.
- **Pins.** Album cards offer **Add to Sidebar** and **Delete Album…**; pinned albums show cover and name, open the same browser and saved position, and offer **Remove from Sidebar**, **Delete Album…** and the four download commands. Deleting an owned normal album asks for confirmation and does not delete its photos or videos. Owned normal albums can be renamed from cards and pins. Pins persist per account and NAS, remain available offline, and are removed only when a verified complete album list no longer contains them.
- **Owner sharing.** Owners can enable private sharing, invite NAS users as Viewers, Downloaders or Providers, change or remove grants, copy the link, and disable sharing from the album header. They can choose public viewing or downloading, return to private access, set or clear a write-only password, and set or clear an expiry (dates end at 23:59:59 in the Mac's time zone).
- **Incoming albums.** Public-link browsing uses a separate sharing context; signed-in invitees open the same album through their regular session with its sharing reference and server-reported permissions. Incoming albums appear under Shared with me and can be browsed and pinned by their owner-scoped identity, with cached or fetched thumbnails. Recipients with a verified download grant can download still photos from the card, browser selection or viewer, and a fresh grant is required for each transfer. Originals, video playback, Live Photo motion, edit, favorites, rotation and adding their items to other albums are unavailable. Provider recipients can contribute Personal Space selections.

Evidence for the sharing behavior: [album sharing summary](capturefindings/album-sharing.md).

## Map

Map shows geotagged photos from the selected Personal or Shared Space library as thumbnail pins and counted clusters. Dense areas group more coarsely to limit the map to 64 annotations; each cluster retains its photos. Opening a pin or cluster creates a session-only filtered collection in the shared browser, showing cached details before network validation. The camera stays useful across metadata invalidation, stale cached pins remain visible when validation fails, and verification is retried automatically. Each space keeps its own full GPS inventory, updated by that space's change feed; a bounded full scan runs only when the inventory is incomplete, and a failed or inconsistent scan keeps the preceding pins. Location labels and antimeridian-specific clustering are not implemented.

## Viewer

Space or double-click opens a photo or ordinary video in the same window. Still photos open from the clicked thumbnail and close back into the current item's live thumbnail; the transitions are smooth even while a larger version loads. The viewer background is white in light appearance and black in dark appearance. Reduce Motion replaces spatial transitions with a short fade.

**Photos.** Arrow navigation, zoom, pan, thumbnail-first loading, optional large previews and originals. A mouse wheel zooms around the pointer (up zooms in) and the zoom control follows. Thumbnails of up to two photos in each direction, and large previews for immediate neighbors when enabled, are fetched ahead, so a cached next photo appears without a blank frame. At fit zoom a horizontal two-finger trackpad swipe pages between items, both following the fingers and snapping past a threshold; a predominantly downward two-finger swipe dismisses like Apple Photos (the photo follows, scales down, the backdrop fades, and releasing past enough distance or speed closes into its thumbnail, otherwise it returns). Above fit zoom two-finger scrolling pans and click-drag never dismisses. Space, Escape or Back closes the viewer. Filename, capture-local date, favorite and the Info panel are available for both media types.

**Video.** Videos keep the thumbnail as a poster until playback begins, have a toolbar mute control synchronized with the native controls and remembered for later videos, use native controls, and stream progressively without downloading the whole file; cached segments are reused. Trackpad swipes over videos navigate or dismiss instead of scrubbing. Settings offers Automatic, Original, High, Medium, Low and Mobile default quality; Automatic targets High. For a converted choice only renditions advertised for the item are used, the closest is chosen when the requested one is absent (the lower one if equally distant), and with none advertised the stored original streams. The toolbar reports the effective rendition and notes a fallback.

**Live Photos** show a corner indicator. After the full still loads, clicking it plays the motion once and a Force Touch press plays until released, with a loading indicator until the first frame. Motion plays without controls and returns to the still, and is unavailable if member lookup fails or the still has been rotated on the NAS.

**Status.** The toolbar title shows the filename, then the capture date and a short status: what is shown, then what is happening. A photo reads, for example, `Medium · Loading`, `Large · Loading 43%`, `Full`, `Large · Decoding`, `Large · Stalled` or `Large · Full unavailable offline`; a video reads `High · Loading`, `High · Buffering`, `Original · Can't play`, or its quality alone while playing. Hovering gives the full description, including whether full resolution came from cache without being checked against the NAS. A thin progress bar appears under the status only for work that goes to the NAS (full-resolution bytes arriving, or a video loading or buffering for more than half a second); cached originals and quickly started videos show none. A load that showed a bar ends with a full green bar for half a second. With large previews enabled the preview fills the first 20% and the original the rest, so the bar never restarts. A load is stalled when no data has arrived for 8 seconds. The library browser has no progress line.

**Inspection tools** (not shown for videos; the toolbar and View menu toggle each). The resizable **filmstrip** shows nearby items in the library thumbnail shape with favorite and video-duration badges. The **histogram** is draggable, snaps to a corner using drag momentum, switches between luminance and additively blended RGB on click (the choice persists), and fades with the backdrop. **Highlight peaking** marks near-neutral bright pixels in the rendered photo in red: a pixel qualifies when its brightest sRGB channel meets the Settings threshold (80% to 100%, default 100%) and its HSV saturation is at most 5%. It is a rendered-image indicator, not a raw sensor clipping detector, and small highlights can be missed. **Focus edges** marks in green the sharpest edges in the photo (one-pixel lines along gradient ridges that continue for about ten pixels; isolated dots and fine texture are ignored), relative to the photo's own sharpest edges with a multiple from 1× to 2.5× (default 1.5×) in Settings. It shows where focus is best, not whether the photo is sharp, so a uniformly soft photo still marks its crispest edges; noise, JPEG artifacts, in-camera sharpening and high-contrast out-of-focus edges can mislead it.

**Pixel interpolation** (Settings): **Always** smooths every displayed image, **Thumbnails Only** smooths provisional thumbnails and large previews until the original is displayed, **Off** disables smoothing. An open viewer updates immediately.

## Info panel

The Cmd+I Info utility panel follows the active viewer item or browser selection. It shows selection totals and date range, resolves aggregate size and media counts, and for a single item shows media-kind icon, filename, copyable item ID and Synology folder path, capture date, a five-star rating (click a star to set it, or the current star to clear it), tag chips, camera and exposure details, dimensions, size, format and available location. Its location map includes every located item in the selection and refits when the selection changes. The panel is transient and excluded from Mission Control and the normal window cycle.

## Activity

One toolbar item opens the Activity panel (also View ▸ Show Activity, ⌥⌘L). Its cloud symbol shows the NAS connection state (slashed when sign-in, the library or the last Refresh failed, with an exclamation mark while failures remain), turns into a rotating sync symbol while work runs, and is filled while the panel is open. A ring shows byte progress when exactly one transfer reports it, and a red dot marks unseen failures. The header shows the connection state and the Refresh button.

- **Activity tab.** Failed work under Needs Attention, then Transfers (downloads, editor handoffs, file promises and uploads, with progress, Cancel, and Show in Finder once saved) and work in progress. A failure opens the panel automatically, at most once every 10 seconds; failed items can be expanded, retried where repeating is safe, and dismissed. Favorites, rotation, ratings, tags, album changes and deletions appear here instead of alerts: browser favorite presses queue rather than being ignored while one is sent, bulk favorites count down as chunks are confirmed, and a failure lists the photos it affected. Failed favorites, ratings and tag changes can be retried per photo; rotation, deletion, album creation and removal cannot. Album rename, sharing and person edits keep inline errors and are recorded in History. Clicking a photo in a failure or History entry selects it when the browser shows its collection.
- **Copy Details** (context menu on failed entries and History records) copies plain text with the app and macOS versions, time, operation, error kind, message, wrapped error types and codes, connection state, collection and affected items, with session, token and credential values removed and without the NAS address or server text.
- **Refresh** shows while it runs; a failed one needs attention and can be retried, and a later success clears it.
- **Notices** report losing the NAS (failed sign-in or library load) and reaching it again, and a full-resolution photo or video that failed in the viewer while the NAS was connected (once per item). Failing to reach the NAS before it has been reached this session (for example launching offline) posts no notice, but a rejected sign-in always does. Notices replace older ones of the same kind, never open the panel and are not part of History. There is no reachability monitor, so a lost connection is noticed only through sign-in, library loading and Refresh.
- **History** summarizes this session's settled changes and transfers, merging consecutive identical bulk changes within a minute. Clear removes settled entries and keeps running ones; nothing persists across launches. Single-photo downloads use the filename, multi-photo downloads their capture-date range.
- Closing the main window or quitting while transfers run asks before cancelling them.

## Cache, freshness and settings

- Timelines, exact pages, albums, location records, thumbnails, previews, originals and previously fetched video ranges are delivered cached-first.
- **Refresh** (Activity panel, Library ▸ Refresh from NAS, ⌘R) reads each space's change feed now and withdraws this run's validation of catalogs and album, folder and summary lists, so they are read again. Nothing is cleared: open views keep their content and merge changes in. With a failed sign-in or an unloaded library it restarts loading instead. Nothing is polled automatically.
- **Revalidate Metadata** (Settings) keeps cached metadata visible but withdraws its verification and the change-feed position, so every timeline, section and detail is read again on demand and by the background sync. It is the escape hatch for changes the feeds missed.
- A metadata-only reset removes timelines, pages, album metadata, locations and session filters while preserving compressed media; a full clear removes metadata and media.
- Change feeds let the app prove untouched Library, folder and tag pages current in both spaces, Personal Favorites, and owned albums that are not shared and whose server version is unchanged. Shared albums, People, Subjects, Recently Added, incoming albums and Shared Favorites are read from the NAS once per run. Evicted details leave known positions intact, and available cached slots remain usable offline.
- Thumbnail rendition changes preserve other cached sizes, and compatible fallbacks stay visible until the selected one arrives. A failed thumbnail offers a retry control on that photo.
- An optional viewer setting loads cached or network-backed large previews alongside originals when the library rendition is smaller.
- A background metadata sync reads every page of Personal Library, Favorites, every owned normal album and every folder (plus Shared Library, Shared Favorites and Shared folders when **Include Shared Space** is on) that is not yet verified this run, at lower priority than visible work, starting with the collection on screen. Failed sections retry automatically with increasing delays, and immediately when the network returns. The Filter popover shows this progress for its timeline. While a pass runs, Activity lists "Syncing library metadata" under work in progress with the current collection, section count and a progress bar; it has no Cancel or dismiss button, disappears when the pass ends or waits to retry, and is not recorded in History.
- **Load All Timeline Sections** is an app-wide metadata warmer for Personal Library, Favorites and every owned normal album; **Include Shared Space** (default on, shared with the thumbnail window) adds Shared Library and Shared Favorites. Start discovers the album list and unopened album timelines, then loads all item pages; Map indexing stays separate. By default it validates every section; **Use Cached Pages** skips complete cached pages and repairs missing detail slots. It downloads no thumbnails.
- **Download Thumbnails** warms Personal Library (optionally including Shared Library through the same preference) for an inclusive populated-day range chosen on a slider; with both libraries, the range applies independently to each. Each job captures its scope at Start and respects the cache budget.
- Demanded video bytes are persisted in fixed-size segments under the same disk budget, with lower retention priority than every photo rendition, and are never prefetched for adjacent videos. A partially cached video is not presented as fully available offline.
- Settings controls thumbnail rendition, large viewer previews, default video quality, pixel interpolation, inspection thresholds and a 200 MB–100 GB budget. The budget limits stored data (cached photo, video and metadata contents), not exact disk use; database overhead and filesystem rounding add a few percent. Settings labels it "Maximum stored data".
- Photo capture times are treated as capture-local wall-clock values: grouping and display preserve the encoded local time without inferring a timezone from the Mac or GPS data.
