# Product

This document is the source of truth for current product behavior and scope. See [ARCHITECTURE.md](ARCHITECTURE.md) for implementation structure and invariants. It describes what users see and can do, not how it is built.

## Purpose and constraints

Cirrus Photos is a macOS 27+ SwiftUI client for browsing a very large Synology Photos library hosted on the NAS `cirrus`. Responsiveness with previously cached data matters more than minimizing request count. The application is an alpha: incompatible preferences and caches are discarded instead of migrated before 1.0.

The Synology Photos service is authoritative. The client does not poll for external changes during a session. Demanded resources are normally validated once per run (thumbnails excepted: a changed thumbnail always gets a new server cache key, so cached thumbnails are not revalidated), while cached content remains usable when the network is slow, unavailable, or validation fails. Pages that the run's change feeds show as unchanged count as validated without being read again.

**Sign-in.** In development builds a `.env` account (README) takes precedence; otherwise, and always in the distributed app, the window asks for server (a bare host means `https://host:5001`; HTTP is rejected), username and password. A sheet asks for the six-digit code when DSM requires one; the Mac then becomes a trusted device. A certificate macOS cannot verify (self-signed or not matching the address), also for `.env`, is shown by SHA-256 fingerprint with **Trust and Connect**; it is then pinned, and a changed one asks again. A new sign-in continues in the same window while the account loads: thumbnail quality and cache size (first sign-in on this Mac only), then **Download Thumbnails?** for a date range (library details sync on their own), then the library.

**Accounts.** Each account's password and device token share one Keychain item; the last account opens at launch. The **Account** menu offers **Switch Account**, **Add Account…** (a separate sign-in window; the library stays open until it succeeds) and **Manage Accounts…** (Settings ▸ Account, where each account has **Switch** and a confirmed **Sign Out…** that also deletes its cache and then opens another saved account or sign-in). The server field suggests the last ten answering addresses and saved accounts' servers. Each account has its own cache and state. Expired sessions renew silently; a rejected stored sign-in closes the account and asks again (`.env` accounts only report it).

## Navigation and collections

The native split-view sidebar contains Library, Favorites, Recently Added, People, Subjects, Tags, Map, and Albums destinations, followed by pinned albums. The app restores the last persistent destination and collection-specific photo/date scroll anchors. Session Map filters are not restored.

The toolbar space selector switches between Personal and Shared Space independently of albums. Shared Space offers cached-first Library, Favorites, People, Subjects, Tags, folders and Map with the same browser, Info, filters, viewer, originals, ranged video, downloads, favorites, rotation, thumbnail rotation, ratings, tags and deletion. Recently Added (no known endpoint) and external-editor handoff are unavailable. Converted video and Live Photo motion use inferred Shared Space counterparts with validated responses; failed converted playback falls back to the original, and unavailable motion stops safely.

**Library and Favorites** show the whole collection in one day-grouped grid. **Folders**: the Library toolbar switches between the timeline and folders in the selected space. Folder mode shows immediate child folders as cover-and-name cards (a folder shows up to four covers: its own, then its subfolders', then its cached photos), with direct photos and videos below in the same scrolling browser, and a leftmost Back button returns to the parent. A folder with child folders but no direct photos leaves the photo area blank; an empty leaf says so. Folder mode and path are restored independently per space and are scoped to the account and server. Only direct photos are included, not descendants.

**People** lists visible recognized people with face covers and item counts. Opening a person reuses the shared browser, viewer, selection and metadata filters. A person card's Rename command changes the name; as a name is typed, matching named people in the same space appear with face thumbnails, and choosing one makes it a merge target. Merging asks for confirmation and the target identity is retained. The result is confirmed by refreshing the server index, and an uncertain outcome is reported for review before retrying.

**Subjects** lists Synology's recognized categories with cover and count; opening one shows its photos in the shared browser. Subject management is not implemented.

**Tags** lists Synology tags with cover and count; opening one shows its photos. Tags are assigned and removed from photos (see Actions); to find photos by tag within a library, favorites, folder or album, use the Tags and Rating criteria of the filter instead of opening the tag.

**Recently Added** shows the NAS collection grouped by indexing day and ordered by the server. Capture dates remain available in photo metadata. Membership is determined by the NAS, not by a client-side age threshold.

People, Subjects, Tags, folders and Recently Added are cached-first and remain available when validation fails. Back or Escape returns from an opened person, subject, tag, album or map result.

## Browsing and selection

- Collections share a virtualized fixed grid with 3–10 square slots per row and a small leading content inset. The thumbnail-size slider and Cmd +/- also set the cards per row in the Albums overview and the People, Subjects, Tags and folder grids. Toolbar buttons beside the size control and the View menu toggle the persisted **Crop Thumbnails to Square** (animating the visible frame within each slot, immediate with Reduce Motion) and **Group by Day** (off: one continuous grid without dates or day breaks) preferences.
- The compact day navigator gives equal space to each populated day and appears near the pointer or with keyboard focus. A persisted option can instead keep its rail and current selection visible while idle.
- Click, Shift-click, Shift-Option-click range selection, marquee, Shift-marquee, Cmd+A, and menu-backed arrow commands select across day and page boundaries.
- Edit > Copy (Cmd+C) on a browser selection copies one `filename,id` line per item (no header, CSV-quoted where needed), resolving unloaded items first. It never copies files (Finder and Photos ignore pasted file promises); drag and drop provides them.
- A session-only metadata filter covers Personal and Shared Library, Favorites, folders, albums, incoming albums and Map results. Criteria: filename, media kind, camera, lens, file extension, tags (any selected), rating (any, unrated, or at least one to five stars), megapixels, size, ISO, focal length, aperture and shutter speed. It uses cached metadata only, so it works offline. Filename search is a case- and diacritic-insensitive substring, or with `.*` a case-insensitive regular expression. Matches from cached pages appear at once and grow as sync and browsing cache more; scrolling near the results' edge requests nearby sections first, and failed sections can be retried. Camera, lens and extension options are cached per collection. Filters clear when the source collection changes and are not restored; Map filtering stays within the selected pin or cluster.

## Actions on photos

- **Favorites** appear as heart badges. The toolbar and Photo menu `.` command toggle the active viewer photo or browser selection, with confirmation when more than five items are affected or the entire collection is selected. Favorite writes are optimistic and serialized; a failure removes the pending state. A Favorites viewer keeps its opening playlist while membership changes.
- **Delete…** (Command-Delete in the Edit menu, and the browser context menu) permanently deletes selected photos and videos from Personal Space, Shared Space, or an owned album's verified members. A confirmation sheet warns first; confirming closes it and the deletion runs in the Activity panel. Afterwards the app reads the items back, reports any that remain, and reloads all collections. Deleting from an album deletes the item everywhere, unlike **Remove from Album…**. Deletion from the viewer, mixed Personal/Shared selections and incoming albums are unavailable.
- **Rating and tags.** The browser context menu, the viewer context menu and the Photo menu set a rating of zero to five stars (digit keys 0–5 in the Photo menu), **Add Tag** (an existing tag, or **New Tag…**) and **Remove Tag**, on the viewer photo or browser selection in Personal Space, Shared Space and owned albums. Tags are listed from the item's own space, so albums offer only **New Tag…**. Edits are not optimistic: the app writes, reads the photos back, and updates the cached rating and tags and the open browser and viewer. Incoming albums and mixed-space selections are unavailable. Tags are not renamed or deleted; a tag disappears when its last photo loses it.
- **Rotation.** Toolbar controls rotate the viewer photo or browser selection left or right, optimistically, for photos and Live Photo stills (videos are skipped), adopting the NAS's refreshed orientation, resolution and thumbnails. Library ▸ Thumbnail Maintenance rotates only the server's small, medium and large thumbnails, leaving the original, in a cancellable progress sheet with a per-photo log. **Fix Thumbnail Rotations** compares the full image with each thumbnail and changes a photo only when all three thumbnails agree confidently; a failed or cancelled repair restores them. Shared Space thumbnail regeneration uses unverified inferred counterparts.
- **Downloads.** The photo context menus in browsers and the viewer download originals or compressed JPEGs to the configured folder (default Downloads) or a chosen one, for the clicked photo or the selection it belongs to; videos are skipped. A single original can reuse cached full-resolution bytes; other downloads unzip the server's ZIP into a folder named after the archive. Files are staged, only completed files are placed, and existing files are never overwritten.
- **Edit With** (same menus) works on the photo under the pointer even when several are selected. macOS lists applications registered for the file type, with an **Other…** chooser. The app creates a separate original copy in `Documents/Cirrus Photos Edits`, keeps existing copies, and opens the copy in the chosen application. Editor changes stay local and are not uploaded. RAW files indexed as Photos items use the same path; separate unindexed RAW or sidecar files are not discovered.
- **Drag out.** Dragging photos from a browser or the viewer to a file-promise destination copies their originals (Live Photo stills; videos skipped). Loaded photos with distinct names arrive as separate files, otherwise as one folder. Each appears at once as a placeholder with a cancellable progress pie; downloading starts on drop, reported in Activity. The preview shows up to 20 thumbnails, with one count. Text fields receive the `filename,id` text when all items are loaded. At viewer fit zoom dragging the image starts a drag; zoomed in it pans. Marquee selection starts on empty browser space.
- **Upload.** Drop local photo or video files on a Personal or Shared library timeline, the folder shown in Personal folder view (exactly that folder), or an owned album's browser, card or pin. Local files are kept and the NAS ignores duplicates (an existing item can still join an album). Each drop is one Activity entry with progress, Cancel, per-file errors and retry; success or an uncertain result refreshes the affected library and album. New thumbnails can take about a minute. Incoming albums and watched folders are unsupported; Shared Space folder uploads are unverified.

## Albums and sharing

On the NAS, sharing an owned normal album adds access settings to that same album, which stays in the normal album list. A shared album is distinct from Synology's Shared Space. Albums retain their own authority and ignore the selected space.

- **Overview.** Albums shows Albums, Shared Albums, and Shared with me in that order, each limited to one responsive row with independently persisted expansion; a persisted sort orders each section by name (default), newest or oldest creation time. The toolbar's plus button creates an empty album. Cards show cover, name and item count. Owned cards offer the four photo download commands for the complete album without opening it; videos are skipped and an empty or video-only album reports no eligible photos.
- **Opened album.** Reuses the shared browser with a scrolling header of cover, name, capture-date range, sharing status and recipient avatars (with hover names), also while loading or when empty or filtered. Escape or Back returns to the overview.
- **Members.** Owned albums can hold Personal and Shared Space members together, including contextual thumbnails, details and original stills. Item actions and downloads need fresh matching reads that establish one source space for the whole selection; ambiguous or mixed-space operations report an error. Album video and Shared Space album contribution are unavailable. Live Photo motion works in owned albums once the member's space is verified on demand; an ambiguous origin stops motion safely.
- **Adding and removing.** Library ▸ **New Album…** and Photo ▸ **Add to Album…** / **Remove from Album…** act on the browser selection; photo and video context menus offer **Add to Album** (including **New Album…** and eligible sidebar pins first) and, in normal albums, **Remove from Album…**, which removes membership without deleting library items. The chooser lists albums the server reports as addable. Operations capture and verify their selection before writing. The sheet shows the selection size, keeps a failed album list open with its error, closes on submit; menu and drag additions open no sheet, and album writes run one after another in the Activity panel. Shared Space selections use the same commands; contributing them to Shared with me albums is unavailable.
- **Dragging.** Drag a Personal or Shared Space browser selection, or the viewer photo, onto an owned album card or pinned row to add its photos and videos (existing members are skipped), or, for Personal selections only, onto a Shared with me album when the recipient has Provider access. Hover over Albums in the sidebar to open the overview during a drag. Drag an owned album card or pin to a file-promise destination to export its eligible originals as an album-named folder. Drag a card to the sidebar to pin it, or a pin to reorder. Internal drops do not start downloads.
- **Pins.** Album cards offer **Add to Sidebar** and **Delete Album…**; pinned albums show cover and name, open the same browser and saved position, and offer **Remove from Sidebar**, **Delete Album…** and the four download commands. Deleting an owned normal album asks for confirmation and does not delete its photos or videos. Owned normal albums can be renamed from cards and pins. Pins persist per account and NAS, remain available offline, and are removed only when a verified complete album list no longer contains them.
- **Owner sharing.** Owners can enable private sharing, invite NAS users as Viewers, Downloaders or Providers, change or remove grants, copy the link, and disable sharing from the album header. They can choose public viewing or downloading, return to private access, set or clear a write-only password, and set or clear an expiry (dates end at 23:59:59 in the Mac's time zone).
- **Incoming albums.** Public-link browsing uses a separate sharing context; signed-in invitees open the same album through their regular session with its sharing reference and server-reported permissions. Incoming albums appear under Shared with me and can be browsed and pinned by their owner-scoped identity, with cached or fetched thumbnails. Recipients with a verified download grant can download still photos from the card, browser selection or viewer, and a fresh grant is required for each transfer. Originals, video playback, Live Photo motion, edit, favorites, rotation and adding their items to other albums are unavailable. Provider recipients can contribute Personal Space selections.

Evidence for the sharing behavior: [album sharing summary](capturefindings/album-sharing.md).

## Map

Map shows geotagged photos from the selected Personal or Shared Space library as thumbnail pins and counted clusters. Dense areas group more coarsely to limit the map to 64 annotations; each cluster retains its photos. Opening a pin or cluster creates a session-only filtered collection in the shared browser, showing cached details before network validation. The camera stays useful across metadata invalidation, stale cached pins remain visible when validation fails, and verification is retried automatically. Each space keeps its own full GPS inventory, updated by that space's change feed; a bounded full scan runs only when the inventory is incomplete, and a failed or inconsistent scan keeps the preceding pins. Location labels are not implemented.

## Viewer

Space or double-click opens a photo or ordinary video in the same window. Still photos open from the clicked thumbnail and close back into the current item's live thumbnail; the transitions are smooth even while a larger version loads. The viewer background is white in light appearance and black in dark appearance. Reduce Motion replaces spatial transitions with a short fade.

**Photos.** Arrow navigation, zoom, pan, thumbnail-first loading, optional large previews and originals. A mouse wheel zooms around the pointer (up zooms in) and the zoom control follows. Thumbnails of up to two photos in each direction, and large previews for immediate neighbors when enabled, are fetched ahead, so a cached next photo appears without a blank frame. At fit zoom a horizontal two-finger trackpad swipe pages between items, both following the fingers and snapping past a threshold; a predominantly downward two-finger swipe dismisses like Apple Photos (the photo follows, scales down, the backdrop fades, and releasing past enough distance or speed closes into its thumbnail, otherwise it returns). Above fit zoom two-finger scrolling pans and click-drag never dismisses. Space, Escape or Back closes the viewer. Filename, capture-local date, favorite and the Info panel are available for both media types.

**Video.** Videos keep the thumbnail as a poster until playback begins, have a toolbar mute control synchronized with the native controls and remembered for later videos, use native controls, and stream progressively without downloading the whole file; cached segments are reused. Trackpad swipes over videos navigate or dismiss instead of scrubbing. Settings offers Automatic, Original, High, Medium, Low and Mobile default quality; Automatic targets High. For a converted choice only renditions advertised for the item are used, the closest is chosen when the requested one is absent (the lower one if equally distant), and with none advertised the stored original streams. The toolbar reports the effective rendition and notes a fallback.

**Live Photos** show a corner indicator. After the full still loads, clicking it plays the motion once and a Force Touch press plays until released, with a loading indicator until the first frame. Motion plays without controls and returns to the still, and is unavailable if member lookup fails or the still has been rotated on the NAS.

**Status.** The toolbar title shows filename, capture date and a short status of what is shown and what is happening, such as `Medium · Loading`, `Large · Loading 43%`, `Full`, `Large · Stalled`, `Large · Full unavailable offline`, `High · Buffering` or `Original · Can't play`; hovering gives the full description, including full resolution taken from cache unchecked. A thin progress bar appears only for NAS work (full-resolution bytes, or video loading or buffering over half a second) and ends with a full green bar for half a second; with large previews the preview fills its first 20%. A load stalls after 8 seconds without data. The library browser has no progress line.

**Inspection tools** (photos only; View menu, and toolbar buttons when enabled in Settings, default off). The resizable **filmstrip** shows nearby items with favorite and duration badges. The **histogram** can be dragged, snaps to a corner with momentum, toggles luminance or blended RGB on click (persisted) and fades with the backdrop. **Highlight peaking** marks in red near-neutral pixels whose brightest sRGB channel meets the Settings threshold (80–100%, default 100%) with HSV saturation at most 5%; it reads the rendered image, not raw clipping. **Focus edges** marks in green the sharpest edges (one-pixel ridges continuing about ten pixels) relative to the photo's own best, by a multiple of 1×–2.5× (default 1.5×); it shows where focus is best, not whether the photo is sharp, and noise, compression, sharpening and contrasty blur can mislead it.

**Pixel interpolation** (Settings): **Always** smooths every displayed image, **Thumbnails Only** smooths provisional thumbnails and large previews until the original is displayed, **Off** disables smoothing. An open viewer updates immediately.

## Info panel

The Cmd+I Info utility panel follows the active viewer item or browser selection. It shows selection totals and date range, resolves aggregate size and media counts, and for a single item shows media-kind icon, filename, copyable item ID and Synology folder path, capture date, a five-star rating (click a star to set it, or the current star to clear it), tag chips, camera and exposure details, dimensions, size, format and available location. Its location map includes every located item in the selection and refits when the selection changes. The panel is transient and excluded from Mission Control and the normal window cycle.

## Activity

One toolbar item opens the Activity panel (also View ▸ Show Activity, ⌥⌘L). Its cloud symbol shows the NAS connection state (slashed when sign-in, the library or the last Refresh failed, with an exclamation mark while failures remain), turns into a rotating sync symbol while work runs, and is filled while the panel is open. A ring shows byte progress when exactly one transfer reports it, and a red dot marks unseen failures. The header shows the connection state and the Refresh button.

- **Activity tab.** Needs Attention, then Transfers (downloads, editor handoffs, file promises, uploads: progress, Cancel, Show in Finder) and work in progress. A failure opens the panel at most once every 10 seconds; failed items can be expanded, retried where safe, and dismissed. Favorites, rotation, ratings, tags, album changes and deletions report here instead of alerts: favorite presses queue while one is sent, bulk favorites count down per confirmed chunk, and failures list their photos. Favorites, ratings and tags retry per photo; rotation, deletion, album creation and removal do not. Album rename, sharing and person edits keep inline errors and are recorded in History. Clicking a photo in an entry selects it when its collection is shown.
- **Copy Details** (context menu on failed entries and History records) copies plain text with the app and macOS versions, time, operation, error kind, message, wrapped error types and codes, connection state, collection and affected items, with session, token and credential values removed and without the NAS address or server text.
- **Help menu.** **Report an Issue…** opens a prefilled GitHub bug report (also in Settings ▸ About). **Export Logs…** saves the app's log from the last 24 hours to a file to attach; nothing is sent.
- **Refresh** shows while it runs; a failed one needs attention and can be retried, and a later success clears it.
- **Notices** report losing and regaining the NAS (failed sign-in or library load) and a full-resolution photo or video that failed in the viewer while connected (once per item). An unreachable NAS before the first connection this session posts none; a rejected sign-in always does. Notices replace older ones of their kind, never open the panel and are not in History.
- **History** summarizes this session's settled changes and transfers, merging consecutive identical bulk changes within a minute. Clear removes settled entries; nothing persists across launches. Single-photo downloads use the filename, multi-photo downloads their capture-date range.
- Closing the main window or quitting while transfers run asks before cancelling them.

## Cache, freshness and settings

- Timelines, exact pages, albums, location records, thumbnails, previews, originals and previously fetched video ranges are delivered cached-first. The distributed app stores them in `~/Library/Application Support/io.github.finia2na.cirrusphotos/`; development builds use the checkout's `.cache/`.
- **Refresh** (Activity panel, Library ▸ Refresh from NAS, ⌘R) reads each space's change feed now and withdraws this run's validation of catalogs and album, folder and summary lists, so they are read again. Nothing is cleared: open views keep their content and merge changes in. With a failed sign-in or an unloaded library it restarts loading instead. Nothing is polled automatically.
- **Revalidate metadata** (Settings ▸ Storage) keeps cached metadata visible but withdraws its verification and the change-feed position, so every timeline, section and detail is read again on demand and by the background sync. It is the escape hatch for changes the feeds missed.
- A metadata-only reset removes timelines, pages, album metadata, locations and session filters while preserving compressed media; a full clear removes metadata and media.
- Change feeds let the app prove untouched Library, folder and tag pages current in both spaces, Personal Favorites, and owned albums that are not shared and whose server version is unchanged. Shared albums, People, Subjects, Recently Added, incoming albums and Shared Favorites are read from the NAS once per run. Evicted details leave known positions intact, and available cached slots remain usable offline.
- Thumbnail rendition changes preserve other cached sizes, and compatible fallbacks stay visible until the selected one arrives. A failed thumbnail offers a retry control on that photo.
- An optional viewer setting loads cached or network-backed large previews alongside originals when the library rendition is smaller.
- A background metadata sync reads every page not yet verified this run of Personal Library, Favorites, owned normal albums and folders (plus the Shared ones with **Include Shared Space**), below visible work and starting with the collection on screen. Pages load while collections and folders are still being discovered, library first. Failed sections retry with increasing delays and immediately when the network returns. The Filter popover shows its progress; Activity shows "Syncing library metadata" with two bars while a pass runs: collections discovered, and sections loaded with the current collection, without Cancel and outside History.
- **Load All Timeline Sections…** (Library menu) loads every item page of Personal Library, Favorites and owned normal albums (plus Shared Library and Favorites with **Include Shared Space**, shared with the thumbnail window), discovering albums first; Map indexing stays separate. **Skip sections already cached** (default on) skips complete pages and repairs missing details. It downloads no thumbnails and continues after its window closes.
- **Download Thumbnails…** (Library menu, Settings ▸ Storage) downloads thumbnails at the Settings quality for an inclusive range of populated days in Personal Library and optionally Shared Library as an Activity entry. It is saved per account and resumes after the window closes, the app restarts or the account reopens; it ends when finished, at sign-out, or when stopping is confirmed (Activity Cancel or **Stop…**). Near a full cache it pauses and offers a larger maximum, which continues it, or stopping.
- Demanded video bytes are persisted in fixed-size segments under the same disk budget, with lower retention priority than every photo rendition, and are never prefetched for adjacent videos. A partially cached video is not presented as fully available offline.
- Settings tabs: **General** (download folder), **Viewing** (thumbnail quality, large previews, pixel interpolation, default video quality, inspection thresholds), **Storage** (200 MB–100 GB maximum shared by all accounts, trimming the least recently opened, usage, one bar of every cached account against the maximum, optionally split into metadata, thumbnails, large previews, full-size photos and video; offline downloads, revalidate, clear metadata, clear all after confirmation) **Account** and **About** (version; in distribution builds, automatic update checks, optional automatic download and install (off by default), **Check for Updates…** and the last check date; website, source, issue link, GPL-3.0 license, third-party acknowledgements with license texts). It counts stored contents.
- Photo capture times are treated as capture-local wall-clock values: grouping and display preserve the encoded local time without inferring a timezone from the Mac or GPS data.
