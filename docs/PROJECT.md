# Product

This document is the source of truth for current product behavior and scope. See [ARCHITECTURE.md](ARCHITECTURE.md) for implementation structure and invariants.

## Purpose and constraints

SynoTimeline is a macOS 27+ SwiftUI client for browsing a very large Synology Photos library hosted on `cirrus`. Responsiveness with previously cached data matters more than minimizing request count. The application is an alpha: incompatible preferences and caches are discarded instead of migrated before 1.0.

The Synology Photos service is authoritative. The client does not poll for external changes during a session. Demanded resources are normally validated once per run, while cached content remains usable when the network is slow, unavailable, or validation fails.

Authentication uses `USER` and `PW` from `.env`; `OTP` is optional for accounts without two-factor authentication. If the NAS requires it, login reports an error asking for `OTP`.

## Current product surface

The native split-view sidebar contains Library, Favorites, Map, and Albums destinations. The app restores the last persistent destination and collection-specific photo/date scroll anchors. Session Map filters are not restored.

### Library, Favorites, and albums

- Personal Library and Favorites share a virtualized, day-grouped fixed grid with 3–10 square slots per row, a small leading content inset, and a persisted preference for aspect-fitted or square-cropped thumbnails. The preference applies to every shared browser and does not change slot, row, or document geometry. A toolbar button beside the thumbnail-size control in each shared browser and the Library menu's **Crop Thumbnails to Square** command toggle the same preference; the button's symbol shows the resulting action (crop to square or fit to aspect ratio). Toggling animates only the thumbnail's visible frame within each fixed slot over a short ease-in-out morph, in both directions and without reissuing media work. With Reduce Motion on, the new presentation applies immediately and newly materialized rows appear directly in the current mode.
- The compact day navigator gives equal space to each populated day and appears near the pointer or with keyboard focus. A persisted option can instead keep its rail and current selection visible while idle.
- Click, Shift-click, Shift-Option-click range selection, marquee, Shift-marquee, Cmd+A, and menu-backed arrow commands select across day and page boundaries.
- Favorites appear as heart badges. The toolbar and Library menu `.` command toggle the active viewer photo or browser selection, with confirmation when more than five items are affected or the entire collection is selected.
- Toolbar controls rotate the active viewer photo or the current browser selection left or right. Rotation is optimistic, supports photos and Live Photo stills, and adopts refreshed orientation, resolution, and thumbnail descriptors from the NAS; videos are skipped.
- Albums shows read-only Personal Space album cards with cover, name, and item count. Opening an album reuses the shared browser with collection-scoped restoration; Escape returns from an opened album or map result just as its Back button does.
- Album creation, rename, deletion, membership changes, and Shared Space browsing are not implemented.
- Personal Library has a session-only metadata filter for media kind, camera, lens, literal file extension, megapixels, size, ISO, focal length, aperture, and shutter speed. Applying a filter immediately shows matches from metadata already indexed. Background discovery adds other cached pages from the current validated timeline, including noncontiguous older pages, to results and option catalogs. Pages cached later by browsing or either warmer update the filter catalog and active results through the repository. Filtered browsers show available cached matches before network validation finishes and retain them when validation fails. Results expand cached-first in bounded batches when the user scrolls toward newer or older results. Empty results retain a **Load More Results** fallback because they have no scrollable source anchor. Filter criteria and coverage are not restored after relaunch, and other collections are unchanged.

### Map

Map shows geotagged Personal Library photos as thumbnail pins and counted clusters. Dense areas group more coarsely to limit the map to 64 annotations; each cluster retains its photos. Opening a pin or cluster creates a session-only filtered collection and reuses the shared browser. Cached canonical item details are shown in their exact ID slots before network validation. The camera remains useful across metadata invalidation; stale cached pins remain visible and are identified as unverified when validation fails.

Location labels and antimeridian-specific clustering are not implemented.

### Viewer and Info panel

The viewer can show a resizable filmstrip of nearby items, a draggable histogram, and red highlight peaking for near-neutral bright pixels in the rendered photo. A pixel qualifies when its brightest sRGB channel meets the threshold and its HSV saturation is at most 5%; for example, (244, 243, 255) qualifies at 100%, but saturated red does not. The 5% neutral-color tolerance is a practical heuristic rather than a universal clipping standard. Settings controls the brightness threshold from 80% to 100%, defaulting to 100%; changes apply immediately and persist. This is a rendered-image white highlight indicator, not a raw sensor clipping detector. The filmstrip follows the library thumbnail shape setting and displays favorite and video duration badges. Clicking the histogram switches between luminance and additively blended RGB channels; this choice persists across viewer sessions and app launches. The histogram stays below the toolbar, animates to a corner using drag momentum on release, and fades with the viewer backdrop during dismissal. The toolbar and View menu toggle each tool. The histogram samples the currently displayed photo; peaking checks up to four samples per overlay pixel after bounded downscaling and shows their coverage; small highlights can be missed or blended away. Both update as the displayed image changes; videos do not show these inspection tools.

Space or double-click opens a photo or ordinary video in the same window. Photos support arrow navigation, zoom, pan, thumbnail-first loading, cached large previews, and originals. Configured thumbnails for up to two photos in each direction and, when enabled and available, large previews for immediate neighbors are fetched and decoded ahead of navigation, so a cached next photo can appear without a blank frame or loading indicator. At fit zoom, a horizontal two-finger trackpad swipe pages interactively between adjacent items: both items follow the fingers and release past a threshold snaps to the neighbor; above fit zoom horizontal scrolling pans instead. Videos retain the thumbnail as a poster until playback begins, provide a toolbar mute control synchronized with native controls and remembered for future videos, use native playback controls, and stream authenticated byte ranges without first downloading the whole file. Arrow navigation remains previous/next and Space, Escape, or Back closes the viewer. Filename, capture-local date, favorite mutation, and the Info panel remain available for both media types. Live Photos display an image-corner indicator. After the full still loads, clicking it plays the motion once, while a Force Touch press plays until released; a loading indicator appears until the first frame is ready. Motion plays without controls and returns to the still afterward. Motion is unavailable if member lookup fails or the still has been rotated on the NAS.

Still photos open from the clicked thumbnail and close back into the current item's live thumbnail. Both transitions are compositor-backed, so a large preview or original upgrade never makes them stutter. The viewer background is white in light appearance and black in dark appearance. At fit zoom a predominantly downward two-finger trackpad swipe dismisses the current item the way Apple Photos does: the photo follows the gesture, scales down subtly, and the backdrop fades to reveal the library. Releasing after enough downward distance or speed sends the photo into its current thumbnail; releasing below that threshold returns it smoothly to full screen. Two-finger scrolling pans whenever the photo is zoomed, and click-drag never dismisses. Reduce Motion replaces the spatial dismissal with a short fade. Trackpad swipes over videos navigate or dismiss instead of scrubbing; native controls still provide seeking.

Settings provides Automatic, Original, High, Medium, Low, and Mobile default video quality choices. Automatic targets High. For a converted choice, the app uses only renditions advertised by the current item; if the requested quality is absent, it chooses the closest advertised quality and prefers the lower one when equally distant. If no converted rendition is advertised, it streams the stored original. The toolbar reports the effective rendition and identifies an unavailable requested quality when fallback occurs.

Settings also controls pixel interpolation in the photo viewer. **Always** smooths every displayed image, **Thumbnails Only** smooths provisional thumbnails and large previews until the original is displayed, and **Off** disables smoothing. The preference updates an open viewer immediately.

The Cmd+I Info utility panel follows the active viewer item or browser selection. It shows selection totals and date range, resolves aggregate size and media counts, and shows a single item's media-kind icon, filename, copyable item ID and available Synology folder path, capture date, camera/exposure details, dimensions, size, format, and available location context. Its location map includes every located item in the selection and refits to the pins when the selection changes. It is transient and excluded from Mission Control and the normal window cycle.

## Cache and network behavior

- Timelines, exact pages, albums, location records, thumbnails, previews, originals, and previously fetched video ranges are delivered cached-first.
- One repository-owned metadata lifecycle coordinates admission, shared jobs, stale-result rejection, storage generations, atomic same-row commits, and successful invalidation revisions.
- A metadata-only Settings reset removes timelines, pages, album metadata, locations, and session filters while preserving compressed media, validators, decoded thumbnails, and already admitted media transfers. Full clear removes metadata and media.
- One repository-owned engine serves all collections. Bounded terminal item Diff v7 intervals can reconcile canonical content and compact Map coverage across runs. Favorites, albums and favorite annotations still require authoritative reads per run; unsupported or ambiguous intervals recover conservatively.
- Logical metadata pages contain at most 250 items from one day. Network batches combine adjacent demand, so small days do not each require a request. Evicted details leave known IDs and positions intact; available cached slots remain usable offline.
- Thumbnail rendition changes preserve other cached sizes. Compatible fallback renditions remain visible until the selected rendition is available.
- A failed thumbnail request offers a retry control on that photo; any cached fallback stays visible while retrying.
- An optional viewer setting loads cached or network-backed `xl` previews alongside originals when the library rendition is smaller.
- The Library menu can warm the selected thumbnail rendition for an inclusive populated-day range using bounded, cancellable background work.
- **Load All Timeline Sections** is an app-wide metadata warmer for Personal Library, Favorites, and every normal Personal Space album. Pressing Start discovers the album list and unopened album timelines, then loads all of their item pages; Map/location indexing remains separate. By default it bypasses stored pages and validates every section; **Use Cached Pages** skips complete cached pages and repairs missing detail slots. It does not download thumbnail bytes.
- Demanded video bytes are persisted in fixed-size segments under the same disk budget. They have lower retention priority than every photo rendition, use a separate two-transfer lane, and are never prefetched for adjacent videos. A partially cached video is not presented as fully available offline.
- Settings controls thumbnail rendition, large viewer previews, default video quality, and a 200 MB–100 GB disk budget.

## Mutations and freshness

Favorite writes are optimistic and serialized. Pending values are presentation overlays; only confirmed chunks patch canonical favorite fields. Failure removes the overlay, and successful writes refresh authoritative Favorites membership. Rotation patches only its owned fields, preserving concurrent favorite changes. A Favorites viewer preserves its opening playlist while membership changes.

Normal photo rotation is available in the toolbar for the active viewer item or browser selection. The native Edit menu contains icon-labeled left/right commands for both normal and thumbnail-only rotation plus “Fix Thumbnail Rotations…”. Normal rotation changes Synology's display orientation and generated renditions without modifying original bytes. Thumbnail-only rotation runs in a modal, cancellable progress workflow: it downloads `sm`, `m`, and `xl`, rotates JPEG bytes locally, replaces only those server renditions through the confirmed regeneration workflow, refreshes descriptors, and leaves original bytes plus orientation/resolution metadata unchanged. Its smoothly animated per-photo progress bar assigns one half to downloads, one sixth to local work, and one third to upload. The download half is weighted by estimated thumbnail sizes and the original's known filesize, uses live byte progress for the full photo, and names the active small, medium, large, or full-photo transfer. The scrollable result log contains one outcome per photo: the applied rotation, already correct, or failure reason. Automatic repair also obtains the full image, uses ImageIO to compare all four relative rotations of each rendition against its intended display orientation, and uploads only when `sm`, `m`, and `xl` independently make the same confident choice. Already-correct, ambiguous, undecodable, missing, or disagreeing renditions are not mutated. Post-regeneration failure or cancellation restores each affected thumbnail unit out of regenerating state.

Photo capture times are treated as capture-local wall-clock values. Grouping and display preserve the encoded local time without inferring a timezone from the Mac or GPS data.

## Deferred scope

Generated people/subject albums, filtering outside Personal Library, Shared Space browsing, place names, upload, sharing, album writes, and coordinated session renewal after expiry remain future work. New collection types should reuse the repository and shared browser rather than introduce destination-specific cache systems.
